# recovery-vla-panda ― 失敗からの復帰を学習する VLA（シミュレーション）

**失敗から回復するまでの手本（復帰デモ）を、教師のプログラムに意図的に失敗させて自動で作り、学習させるだけで、ロボットアームの VLA は把持に失敗しても自分で掴み直すようになった。**

| 復帰デモあり {{e3a_xk}} 回 ／ なし {{e3a_yk}} 回 |
|---|
| 把持を意図的に失敗させた、同じ配置・同じ失敗の {{e3a_pairs}} 組で、掴み直して成功した回数（復帰デモありで学習したモデルと、なしで学習したモデルの比較。主要評価項目、Holm 補正後 p {{e3a_holmeq}}） |

手軽に再現できる構成

- 実機も、人による遠隔操作やデモ収集も使わない
- 学習データ {{eps_auto}} 本（成功デモ {{n_normal}}・復帰デモ {{n_recovery}}）はすべてスクリプトで自動生成
- GPU 1 枚（{{gpu}}）で、学習 1 回は約 {{train_h}} 時間

**簡単に作れて、難しいことができる。** スクリプトではなく、学習した VLA が動きながら自分で掴み直す。「全部片付けて」では LLM が色の順を決め、VLA が 3 個を一色ずつ運ぶ（3 個とも入ったのは {{e7_k}}/{{e7_n}}）。

効果は学習と同じ種類の把持失敗に限られ、落下・置き損ねからはほとんど復帰しない。行き先は指示文ではなく目標位置の入力で決まっている。実機では確かめていない。

**動画と説明資料**: omnicampus に提出した Zip に、動画（MP4、全 {{v_total}}）と説明資料（PDF）が入っている。動画の冒頭（{{v_contrast}}）は、意図的に失敗させていない試行でロボット自身が掴み損ねた場面を、復帰デモあり・なしで左右に並べたもの。上の数字は、把持を意図的に失敗させた評価によるもので、この映像によるものではない。説明資料の 1 ページ目は、この冒頭と同じ要点である。

---

Physical AI 応用 1 講座の最終課題である。MuJoCo 上の Franka Panda が、日本語による指示（例:「全部片付けて」）に従い、テーブル上の赤・緑・青の立方体を箱へ収納する。VLA（SmolVLA）を、スクリプト化したエキスパートによる成功デモと、**意図的に失敗させた後にエキスパートが復帰する過程を自動で記録した復帰デモ**を用いて追加学習し、人手によるデモ収集を必要とせずに、学習と同じ種類の把持失敗からの復帰成功率を {{e3a_y}} から {{e3a_x}} に高めた。ロボットを動かす実行時の仕組み全体（実行系）は、実機で取得できるセンサの出力（RGB-D カメラ画像・関節の状態・グリッパの開き幅）と、事前に計測・較正して与える既知の情報（ロボットのモデル、テーブル面、立方体と箱の寸法、カメラのパラメータ）のみを用い、シミュレーションの真の状態は参照しない。

- 本リポジトリには、説明資料と動画を生成するスクリプトと原稿（`paper/`）を含む
- 本リポジトリは講師・受講者が参考資料として閲覧することを想定している。チェックポイント・データセット・初期値として用いたモデルは容量が大きいため含めていない（各ファイルの版は `docs/freeze/s3_hashes.json` の SHA-256 の一覧で固定している）

### 三層の制御ループ

| 層 | 周期 | 内容 |
|---|---|---|
| 上位層 | サブタスク単位 | 俯瞰カメラ画像からテーブル上と箱内の色を検出し、Claude Haiku 4.5（構造化出力）が指示をサブタスク列（例: 赤 → 緑 → 青）に分解する。出力はルールで検査し、不正な場合は実行しない。完了は「俯瞰カメラと手首カメラの画像で箱内に当該色が見え、グリッパが開いており、エンドエフェクタが待機位置で {{judge_hold_s}} s 静止している」ことで判定する。{{step_timeout}} s 以内に完了しない場合は、エンドエフェクタを待機位置へ戻してから再試行し、再試行でも完了しなければ停止して報告する |
| VLA 層 | 行動 {{policy_hz}} Hz | SmolVLA（LeRobot の {{init_model}} を初期値として追加学習）。入力は俯瞰・手首カメラ画像、状態 {{state_dim}} 次元（関節角 {{st_joint}}・手先の位置 {{st_pos}}・手先の姿勢のずれ {{st_rot}}・指の開き {{st_finger}} の {{state_base}} 次元と、目標位置の入力 {{cue_dim}} 次元）、英語の指示文である。目標位置の入力は、俯瞰カメラ画像から検出した指示の色の立方体のテーブル面上の位置 (x, y) である。{{chunk}} ステップ × {{act_dim}} 次元のアクションチャンクを Flow Matching により生成する。推論は {{exec_s}} s（{{exec_rows}} ステップ）ごとに始め、結果が届くまでは前のチャンクの続きを実行し、届いたチャンクは観測から経過したステップの分を飛ばした行から実行する（非同期実行、RTC は用いない） |
| 低位制御 | {{phys_hz}} Hz（物理演算の時間刻み {{phys_ms}} ms） | 指令の制限（Franka Panda の公称の上限: 関節と手先の速度・加速度・躍度、グリッパの速さと力）→ 逆運動学。安全フィルタ（推定した障害物との距離に関する不等式制約を満たすよう、エンドエフェクタの指令の変化量を二次計画で置き換える）は実装しているが、評価の結果に基づき最終的な構成からは外した |

推論にかかる時間は、実測した推論時間の分布（中央値 {{lat_p50}} s、{{gpu}} で測定）から推論のたびにサンプリングして模擬する。センサには、公称の仕様から定めた雑音・欠損・量子化・較正誤差・遅延を加えている。実行系が真の状態を参照していないこと、指令が上限を超えていないことは、全試行で監査している（`harness/audit.py`、`eval/gate.py`。違反を含む実行の結果は集計に用いない）。

## 実行方法（Windows、PowerShell）

1. 実行環境の構築（初回はネットワーク接続が必要である。管理者権限は用いず、本フォルダ以下にのみ書き込む）

   ```powershell
   powershell -ExecutionPolicy Bypass -File env\setup_env.ps1
   ```

   uv・Python 3.12・PyTorch（CUDA 12.6）・LeRobot 0.6.1・MuJoCo などを `.venv` に導入し、導入された版が `env/requirements-lock.txt` と一致することを検査する。

   ネットワークに接続せずに別の場所へ構築する場合は、一度構築した場所から `.tools`・`.python`・`.cache\uv` を新しい場所へ複製し、`$env:UV_OFFLINE='1'` を設定してから同じコマンドを実行する。`.python` 内の版のリンク（`cpython-3.12-windows-x86_64-none`、ジャンクション）は複製しない（実体として複製すると `uv python install` が失敗する。存在しない場合は uv が再作成する）。

2. 初期値のモデルとチェックポイントの配置（本リポジトリには含まれていない）

   - `models/hf_home/` に Hugging Face のキャッシュ形式で `lerobot/smolvla_libero` と `HuggingFaceTB/SmolVLM2-500M-Video-Instruct` を配置する
   - 評価に用いるチェックポイントは `outputs/train/<実行名>/checkpoints/020000/pretrained_model` である（一覧とハッシュは `docs/freeze/s3_hashes.json` に記載）
   - `scripts/52_freeze.py verify-s3` により、配置したファイルが一覧と一致するかを確認できる

3. テスト（チェックポイントを必要としないもの）。事前に本セッションの環境変数（`HF_HOME`・`HF_HUB_OFFLINE=1` など）を読み込む。読み込まない場合、Hugging Face への接続を試みて停止することがある

   ```powershell
   . .\env\session_env.example.ps1
   .venv\Scripts\python.exe -m pytest -q -m "not needs_outputs"
   ```

4. 評価の実行例（ネットワーク接続なし。最終構成による意図的な失敗なしの 3 色の試行。`--model R1v3` が復帰デモありで学習した最終モデル、`N1v3` が復帰デモなしで学習した比較対象である）

   ```powershell
   .venv\Scripts\python.exe scripts\82_v2_eval.py run --experiment CHECK --condition A_nat `
     --model R1v3 --mode naive --exec-interval 6 --no-safety --trials natural:198905:1
   ```

   意図的に失敗させる場合は `--trials induced:<シード>:<配置の数> --induce P1`（`P1`: 把持失敗、`P2`: 搬送中の落下、`P3`: 置き損ね）とする。GPU による推論の計算結果は実行のたびにわずかに揺らぐため、再実行の結果は完全には一致しない。

5. 上位層（LLM）を用いる場合に限り、Anthropic API のキーを環境変数で与える（ファイルには記載しない）

   ```powershell
   $env:ANTHROPIC_API_KEY = '...'
   .venv\Scripts\python.exe scripts\82_v2_eval.py task --experiment CHECK --condition task `
     --model R1v3 --exec-interval 6 --no-safety --trials 198905:1 --text 全部片付けて
   ```

- 参考（結果を見た後に加えた集計、`55_extra_s3.py`）: 実際に失敗したかによらず、把持失敗を意図的に起こした {{p1all_n}} 組すべてで成功を比べると {{p1all_xk}}/{{p1all_n}} と {{p1all_yk}}/{{p1all_n}} であった（p {{p1all_peq}}）。意図的な失敗なしの {{nat_gf_trials}} 試行で方策自身が起こした把持失敗からの復帰は、ありが {{nat_gf_xn}} 試行中 {{nat_gf_xk}}、なしが {{nat_gf_yn}} 試行中 {{nat_gf_yk}} であった。同じく方策自身が起こした運ぶ途中の落下は、ありが {{nd_x_n}} 件（うち復帰 {{nd_x_k}}）、なしが {{nd_y_n}} 件、置き損ね（箱の縁・箱のすぐ横）はありが {{nm_x_n}} 件、なしが {{nm_y_n}} 件（復帰はありが {{nm_x_k}}、なしが {{nm_y_k}}）であった
- 最終構成（復帰デモあり、非同期実行、安全フィルタなし）: 意図的な失敗なしの成功率 {{e1_k}}/{{e1_n}}（{{e1_pct}}、95% 信頼区間 {{e1_ci}}）、把持失敗からの復帰率 {{e2_k}}/{{e2_n}}（{{e2_pct}}）。復帰デモなしで学習したモデルの意図的な失敗なしの成功率は {{nat_rn_yk}}/{{nat_rn_pairs}}（{{nat_rn_y}}）であった（p {{nat_rn_peq}}、補正なし）
- RTC: エンドエフェクタの躍度（二乗平均平方根の中央値）は {{jerk_naive}} から {{jerk_rtc}} m/s³ へ下がったが、意図的な失敗なしの成功率は {{nat_nr_x}} から {{nat_nr_y}} へ、把持失敗からの復帰率は {{e4_x}} から {{e4_y}} へ低下し、障害物に接触した試行は {{con_nr_x}} から {{con_nr_y}} へ増えた。RTC を用いないことは検証用のシード範囲での結果から決めており、この比較は本実装・本設定での RTC についてのものである
- 安全フィルタ: 意図的な失敗なしで障害物に接触した試行は、フィルタなしの {{e5_xk}}/{{e5_pairs}} からありの {{e5_yk}}/{{e5_pairs}} へ減った（p {{e5_peq}}）。一方、成功率は {{e5s_x}} から {{e5s_y}} へ下がった（p {{e5s_peq}}）。検証用のシード範囲で事前に定めた規則（ありの成功率がなしより {{sf_rule_pt}} ポイント以上低ければ外す）に従い、最終構成から外した。テスト用のシード範囲でのこの比較は、評価の結果を見た後に追加したものである
- 目標位置の入力: 指示文と目標位置の入力を一緒に差し替えると {{e6_k}}/{{e6_n}} が差し替えた色へ向かった。目標位置の入力だけを差し替えると {{e6c_cue}}/{{e6c_n}} が入力した位置の色へ向かい、指示文の色へ向かったのは {{e6c_text}}/{{e6c_n}} であった（最初のアクションチャンクの行き先を {{e6_samples}} 回の生成の多数決で判定）。方策は行き先を指示文ではなく目標位置の入力で決めている
- 3 個の連続タスク（「全部片付けて」）: 3 個すべてが箱に入ったのは {{e7_k}}/{{e7_n}}（95% 信頼区間 {{e7_ci}}）、停止せずにすべての完了判定が出たのは {{e7_sys}}/{{e7_n}} であった。停止した {{e7_stopped}} 試行のうち {{e7_stop2}} 試行は {{e7_stop_pos}} 番目のサブタスクで停止し、{{e7_stop_all3}} 試行は 3 個とも箱に入っていたが最後の完了判定が出なかった。再試行により完了したサブタスクは {{e7_retry}} 件、完了判定の誤りは未完了を完了とした {{e7_fp}} 件・完了を未完了とした {{e7_fn}} 件であった
- やり直しの回数（3 個の連続タスク、`56_intervention_s3.py`）: {{iv_n}} 回の作業で、やり直しなしで 3 個とも片付いたのは {{iv_sk0}} 回、自動のやり直しを {{iv_k1}} 回まで許すと {{iv_sk1}} 回、{{iv_k2}} 回までで {{iv_sk2}} 回であった。評価中に人は一度も手を出しておらず、介入はすべて上位層の自動のやり直しである（1 試行あたり {{iv_per_run}} 回、うち {{iv_judge_only}} 回は立方体がすでに箱に入っていて完了判定だけが出なかったもの）
- 実行系の監査: 全 {{e9_trials}} 試行で、真の状態の参照・指令の上限超過はいずれも {{e9_viol}} 件であった。画像から推定した立方体の位置の誤差は中央値 {{perc_med_mm}} mm、95 パーセンタイル {{perc_p95_mm}} mm であった

**段階 3 の評価に関する注記**

- 段階 1・2 の最終評価の実行方式（非同期・10 ステップごとに推論・安全フィルタあり）と、段階 3 の実行方式（非同期・{{exec_rows}} ステップごと・安全フィルタなし）は異なる。実行方式は段階 3 の最初に検証用のシード範囲で選び直した
- 段階 3 の 1 周目の学習し直しを採るかどうかは、検証の結果を見た後に、事前に定めた 4 条件のうち前提が崩れた 1 条件を除いて判断した（詳細は `docs/results/results_s3.md` の 6）。この学習し直しによる改善は、復帰デモあり・なしの両方のモデルに生じた

### 限界

- 評価はシミュレーションに限定しており、実機での検証は行っていない
- 評価で起こした把持失敗は学習した復帰デモと同じ種類であり、学習にない種類の失敗への汎化は確かめていない
- 復帰デモは、シミュレーションの真の状態を参照できる教師（立方体の真の位置・速度などを参照するスクリプト化したエキスパート）が失敗と復帰の過程を大量に生成し、それをセンサの出力で動作する方策に学習させたものである。実機で同じ生成手順を用いるには、立方体の姿勢を推定する仕組みと、場面を初期状態へ自動で戻す仕組みが前提となる
- 把持失敗以外からの復帰性能は低い。最終構成でも、搬送中の落下からの復帰は {{a_p2_k}}/{{a_p2_n}}、置き損ねからの復帰は {{a_p3_k}}/{{a_p3_n}} であった
- 方策は行き先を指示文ではなく目標位置の入力で決めており、色の識別は検出器に依存している
- 3 個の連続タスクの成功率は {{e7_k}}/{{e7_n}} にとどまり、{{e7_stop_pos}} 番目のサブタスクでの停止が多い
- 最終構成は安全フィルタを外しており、意図的な失敗なしでも {{e5_x}} の試行で障害物に接触した。接触を減らしつつ成功率を保つ方法は今後の課題である
- 動画の映像は、テスト用の試行を同じ配置・乱数シード・設定で再実行し、評価のときと同じ経過をたどったものである（GPU 上の推論の計算結果がわずかに揺らぐため、完全に同じ映像にはならない）

## 設計の経緯

1. **シーンとエキスパート**: 3 色の立方体と箱（内寸 16 cm）からなるシーンを構築し、真の状態から動作段階（接近・下降・把持・搬送・グリッパを開く・待機）を判定して動作するスクリプト化したエキスパートにより成功デモを生成した
2. **色の識別**: 指示文のみで学習した VLA は、指示された色を識別しなかった（指示を差し替えても同じ立方体へ向かった）。そこで、俯瞰カメラ画像の色検出から得た目標の位置を状態に加える「目標位置の入力」を導入した
3. **復帰デモ**: 成功デモに、意図的に失敗させた後にエキスパートが復帰する過程のみを記録した復帰デモを加えて学習した。比較対象として、同数の成功デモのみで学習したモデルを用意した
4. **センサの出力のみで動作する実行系**: 実行系の入力をセンサの出力と既知の情報のみに限り、立方体の位置を画像から推定するようにした。センサには公称の仕様から定めた雑音・欠損・量子化・較正誤差・遅延を加え、推論時間は実測の分布から推論のたびにサンプリングし、指令は Franka Panda の公称の上限で制限した。真の状態を参照しないこと・上限を超えないことを全試行で監査する仕組みを加えた
5. **段階 1・2**: それまでのモデルをこの実行系で評価した段階 1（テスト用のシード範囲 {{seed_s1}}〜）では、意図的な失敗なしの成功率が {{s1_e1_k}}/{{s1_e1_n}} であった。センサのモデルを通したデータで学習し直した段階 2（{{seed_s2}}〜）でも {{s2_e1_k}}/{{s2_e1_n}}、把持失敗からの復帰率は {{s2_e2_k}}/{{s2_e2_n}}、復帰デモの効果の検定は Holm 補正後 p = {{s2_holm}} であり、事前に定めた失敗の基準（成功率 50% 未満、復帰率 30% 未満、検定 p ≥ {{alpha}}）のすべてに該当した
6. **段階 3（改善、周回の上限 3 周）**: 失敗の解析から、(a) 方策がエンドエフェクタの指令と実際の位置の差（指令の先行）を取り違えて立方体の手前で把持すること、(b) 止まった後の状態が学習データにないこと、を主な原因と判断した
   - 学習を伴わない準備: 学習時のデータの読み出しを高速化し（値は同一）、実行方式を検証用のシード範囲で選び直した（非同期・{{exec_rows}} ステップごと）
   - 1 周目: エキスパートの終盤の接近を遅くして指令の先行を小さくしたデータで、両モデルを学習し直した。検証用のシード範囲で、意図的な失敗なしの成功率は復帰デモありで 53 → 81/99、なしで 39 → 74/99、把持失敗で復帰デモありのみが復帰した組は 17 → 25 となり、採用した（上の注記のとおり、結果を見た後に 1 条件を除いて判断した）
   - 2 周目: 方策の実行中に止まった・位置がずれたまま閉じようとした場面からエキスパートへ引き継いで立て直す過程を、両モデルの学習データに加えたが、事前に定めた条件を満たさず採用しなかった。最終モデルは 1 周目のものとした
   - 安全フィルタ: 最後の学習の後、検証用のシード範囲で、ありの成功率 {{sf_val_on}}/{{sf_val_n}} がなしの {{sf_val_off}}/{{sf_val_n}} より {{sf_val_drop}} ポイント低かったため、最終構成から外した（接触はあり {{sf_val_con_on}}/{{sf_val_n}}、なし {{sf_val_con_off}}/{{sf_val_n}}）
7. **最終評価**: コード・チェックポイント・データを凍結し（`docs/freeze/s3_hashes.json`）、段階 3 のテスト用のシード範囲（{{seed_s3}}〜。段階 1・2 とは別の範囲）で一度だけ評価した

## AI の利用

システム内では、指示のタスク分解に LLM（Claude Haiku 4.5、Anthropic API）を、ロボットアームの制御に VLA（SmolVLA）を用いている。開発においては、コードの作成、実験の実行、結果の集計、説明資料および動画の作成に Claude Code を利用した。評価の設計（主要評価項目と基準）は結果を見る前に定め、本リポジトリと説明資料の数値は結果ファイルからスクリプトにより生成している（この README の数値も、説明資料と同じ値の一覧から書き出し時に差し込んでいる）。
