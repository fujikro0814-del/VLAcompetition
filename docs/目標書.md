# 目標書 v3（2026-10-01 決裁。v2 は 2026-09-29）

## 目的
シミュレーション上の Franka Panda で、実機で得られる情報と実機で可能な動作だけで動く実行系が、人手なしで自動生成した復帰デモの学習によって、作業途中の失敗から復帰できるかを、事前に定めた方法で確かめ、結果の良し悪しによらず報告する。

## 目標（達成の基準と確かめ方）
G1 情報: 実行時の判断（方策・上位層・完了判定・安全フィルタ・実行器・再試行）は、宣言したセンサの出力と、宣言した設置情報だけを使う
  - センサ: 俯瞰 RGB-D、手首 RGB-D、関節の角度・速度、グリッパの開き幅（1 値）
  - 設置情報: ロボットのモデル、テーブル面、立方体と箱の寸法、カメラの内部パラメータ、較正誤差を含む外部パラメータ（手首は hand-eye 較正の誤差を含む）
  - 確かめ方: 実行系はセンサの値の入れ物しか受け取らない構造、真値に触れるコードがないことの自動検査、全試行の監査の記録で違反 0
G2 時間: シミュレーションの時刻の上で、世界は一度も止まらない
  - 推論・待ち・サブタスクの切り替えの間も物理は進み、ロボットはその場で保持する
  - 観測から行動までの遅延は、実測した推論時間とカメラの遅延の分布から、試行の乱数シードで毎回引く。画像は関節の状態よりカメラの遅延の分だけ古い
  - 確かめ方: 全試行で世界の停止 0、引いた遅延の記録
G3 作動: 腕への指令は Franka Panda の公称の上限を常に満たす
  - 関節: 速度 2.175（1〜4 軸）・2.61（5〜7 軸）rad/s、加速度 15・7.5・10・12.5・15・20・20 rad/s²、躍度 7500・3750・5000・6250・7500・10000・10000 rad/s³、トルク 87・12 Nm、トルクの変化 1000 Nm/s
  - 直交座標: 並進の速度 1.7 m/s・加速度 13 m/s²・躍度 6500 m/s³
  - グリッパ: 1 自由度、指 1 本あたり 50 mm/s 以下、把持力は連続 70 N 以下。開閉の判定は測った開き幅
  - 確かめ方: 全試行の指令の記録から上限違反 0 を示す
G4 センサの模型: 深度と色の雑音・欠け・量子化・較正誤差・遅延は、公称の仕様（または実物の測定）から決めた 1 つの版に固定し、実行系のすべての部品（方策の入力を含む）に同じものを使う。評価の途中で変えない
G5 評価: 復帰デモの効果（復帰デモあり R1 対 なし N1、P1 の復帰）と実行系の各部品の寄与を、G1〜G4 を満たす実行系で、未使用のテスト用シード範囲で、回す前に固めた主要評価項目と基準で評価する。結果の良し悪しによらず報告する
G6 提出: 11/2 10:00 までに課題の要件を満たす提出物を出す（目標は 10/31）。主な数字は G5 の評価だけから取る

## 非目標（入れると目標がずれるもの）
- 実機での実演
- 方策の構造・学習手法の変更、課題（物体・動作・指示の種類）の追加（段階 3 で許す学習の設定＝ステップ数・画像の拡張は、学習手法の変更に当たらないものとして扱う。v3）
- 写実的な描画（質感・照明の写実）。センサの雑音と照明のばらつきは G4 の範囲で入れる
- データ生成（エキスパート・失敗注入・場面のリセット）と評価の判定の実機化。データ生成は「特権情報を持つシミュレーション内の教師」として扱い、説明資料にそう書く

## 設置の前提
- テーブル面: 既知（設置時に較正。較正誤差を入れる）。起動時に深度から平面を当てはめ、既知の値とのずれを確かめる
- 箱: 寸法は既知。固定具でテーブルに固定する設置とする。位置と向きは毎回知覚で推定し、実行系は既知の位置を使わない（既知の位置は、ずれの監視にだけ使う）

## 段階と関門（日付は固定）
段階 1: 実行系の現実化（学習済みのモデルはそのまま）
  - 関門 1（10/12）: G1〜G4 の検査がすべて通り、知覚の精度を記録し、閾値・余裕を学習用と検証用のシードだけで決め終える → 段階 1 の最終評価（120000〜）
段階 2（条件つき）: 学習データを同じセンサ・作動の模型で作り直し、R1 と N1 を同じ手順で学習し直す。2 周目（R2・R1+）は行わず、最終モデルは R1
  - 発動の条件（検証用のシードで判定し、結果を見る前に固定）: (a) G3 に合わせるためにエキスパートの動きが変わる、または (b) 方策の入力に G4 の雑音を入れると、失敗注入なしの成功が入れないときより 10 ポイント以上下がる
  - 関門 2（10/17）: 学習と検証用のシードでの確認が終わる → 段階 2 の最終評価（130000〜）
  - 段階 2 の「失敗」の定義（v3。段階 2 の最終評価の結果を見る前に固めた。次のどれか 1 つでも当たれば失敗）:
    - E3 ①（本線の R1v2 対 N1v2、P1 の復帰）が、Holm 補正の後で p < 0.05 にならない
    - 最終モデルの P1 の復帰（E2）が 30% 未満
    - 最終モデルの失敗注入なしの成功（E1）が 50% 未満
段階 3（v3。段階 2 が失敗したときだけ発動）: G1〜G4 を満たす実行系のまま、復帰デモの効果（R 対 N）と復帰の能力を示す
  - 許す改善の範囲（決裁の判断で決める）:
    - データ: 本数を増やす、エキスパートの動きに乱れを加えた実演、方策を走らせてずれた状態からエキスパートに引き継ぐ区間（2 周目の作り方の一般化）
    - 実行の手段: 塊の実行の長さ、行動のならし方など
    - 学習の設定: ステップ数、画像の拡張など
  - R と N の公正さ: 改善は R と N に同じだけ当てる。違いは「失敗注入からの復帰の区間を入れるかどうか」だけにする。方策を走らせて引き継ぐ区間を足す場合は、R と N の両方に同じ作り方で足し、そのことを書く
  - 判断は学習用と検証用の種だけで行う。テスト用の種は最終評価の一度だけ
  - 周回の上限 3 周。最後の学習を始めてよいのは 10/15 まで。最終評価は未使用のテスト用の種（140000〜）で一度だけ、10/20 までに終える
  - 主要評価項目と基準は段階 2 と同じ（E1・E2・E3・E9 など）
主な結果の決め方（v3）: 段階 3 を発動し、その最終評価が 10/20 までに終われば段階 3 を主な結果とする。数字の良し悪しでは選ばない。段階 1・2 も並べて示す。10/20 までに終わらなければ段階 2 を主な結果とし、段階 3 は途中経過として付録に書く（段階 3 を発動しないときは、v2 の決め方のとおり段階 2 を主な結果とする）
凍結 10/22、提出物の完成 10/29、提出 10/31（v3 でも変えない）

## 変更の手続き
- 目標（目的・G1〜G6・非目標・設置の前提・関門の日付）を変えてよいのは、「実現不可能」と判定されたときだけ
- 実現不可能の判定: (a) 技術的に、G の範囲の中で 2 つ以上の独立な方法を試し、測定の証拠で届かないと示した、または (b) 日程の上で、関門の日付を過ぎ、残りの見積もりが締切までの日数を超えた（このときは縮退の順を適用する）
- 「結果が悪い」「見た目が悪い」は理由にならない。悪い結果は結果として報告する
- 申請は掲示板の goal_change の形式で出す（どの目標を・証拠・試したこと・最小の変更・他の目標への影響）。監督の点検の後、決裁が承認したときだけ、版を上げ、この文書の末尾の変更履歴に差分と理由を残す
- 手段（方法・部品・閾値）は、目標を満たす範囲で自由に変えてよい。閾値は学習用と検証用のシードだけで決める
