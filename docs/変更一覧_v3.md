## 確定した扱い（v3 に載せる）

- **作品の方針（2026-09-27 に、R2 の結果を見る前に決めた。0070 の 7）**: 本線の実行は非同期（rtc・s=10・d=4・範囲 40・指数）とし、R2 の結果がどうであっても、その設定での数字をそのまま報告する。R2 で P2 が戻らなかった場合も、本線の設定は変えない。遅れを下げる手を採った場合は、その手で決まった d の非同期が本線になる
- P1 に「閉じる高さを上げる型」は足さない（0068 の 6、0070 の 6 で確定）
- R2 は乙（評価と同じ設定で方策を走らせてから台本に引き継ぐ。P1・P2・P3 各 40、甲 60）。計画は 0069 の 3、承認は 0070 の 1。R2・R1+ の保存点は 5000 手と 10000 手を同じ規則で選ぶ（0070 の 3）
- 丙（B を作り直して R1 を学び直す）は行わない（0070 の 4）。**理由**: 開始の瞬間を合わせるだけでは足りず、遅れの間の動きまで覆う必要がある（手を止める P2 は開始状態が B と合っていても評価の設定で 0/17）
- 自然な失敗の分類の定義は 0069 の 5 に 3 点を足して承認（0070 の 5）: 机の上以外で静止した落下を「その他の落下」に分ける、成功した試行での誤発火を先に検査する、R2 の甲の失敗の検出にも同じ定義を使う

## 結果として書くこと（最終報告の結果の節へ。0068 の 5）

1. **復帰デモの開始状態が、方策が実際に失敗したときの状態と一致しないと、復帰デモは効かない**。評価の P2 では落ちる間も手が方策のまま進み、制御が戻った時点で手は立方体から 7.6 cm（中央値）離れていた。データの B は台本が手を止めて待つ形で、手は 1.0 cm。P2 の 40/40 が B の範囲の外で、R1 の P2 の復帰は 0/40、N1 と差がなかった（25 対で 0 と 0）。この食い違いは 0045 の比較表から漏れていた（0067・0068・0069）
2. **非同期の実行（遅れ d=4）では、失敗の直後の状態が方策の前の計画でさらにずれる**。制御が戻ってから 1 s 以内に、方策は失敗前の「運ぶ」計画を続けて指を閉じ、立方体から離れる（P2 で 40/40）。開始状態を B に合わせても（手を止める診断）、評価の設定では 0/17、naive 1/17、sync 10/19。P3 は開始状態がデータ C とほぼ同じでも、評価の設定で 4/28・sync 14/28。RTC（範囲 40）は前の塊に寄せるので P1 をさらに悪くする（naive 14/29 → 0/25）（0069）
3. **B の開始状態（立方体の真上で指が開いた状態）は通常のデモで既に覆われている**。その状態から sync で R1 10/19、N1 9/18 と差がない（0069）
4. 以上から、復帰データは台本だけで作るのではなく、評価と同じ実行の設定で方策を走らせ、方策が行き着いた状態から引き継いで作る（R2 の乙）
5. **（この課題の中心の結果）遅れのない実行では A の復帰データがはっきり効き、評価の設定（非同期・遅れ d=4）ではその効きが消える**。sync・同じ種の P1 で、両方成立の 24 対のうち R1 15・N1 2（McNemar p = 0.001、差の 95% 区間 +27〜+72 ポイント）。評価の設定では R1 の P1 は 0/25。C の上積みは、この数でははっきりしない（sync の P3 で 28 対のうち 14 と 10、p = 0.42）（0071・0072）
