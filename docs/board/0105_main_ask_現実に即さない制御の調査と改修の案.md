## 要点（3行以内）

実行時の判断にシミュレーションの真値を使っているのは**安全フィルタだけ**（立方体の真の位置・姿勢・形状と、真値での「箱の中か」）。方策・上位層・完了判定・待機位置へ戻す動きは、画像・関節の状態・指令値と、既知と仮定した固定物（箱の位置と寸法・テーブル面・カメラの較正）で動いている。
ほかは理想化（推論中の物理の停止、カメラ遅延なし、雑音のない画像、グリッパの状態を制御器の旗で読む、物性の固定など）と、データ生成・評価だけでの真値の利用（エキスパート・失敗注入・R2 の失敗検出・成否判定・場面のリセット）。
改修の案: 疑似 RGB-D（RealSense 相当）で**立方体も箱も知覚**し、安全フィルタ・箱の中の判定・完了判定をすべて知覚に置き換えた「知覚のみの実行系」を作り、今の結果は残したまま、未使用のシード範囲で改めて評価する。回す前に設計と主な見方を固めて諮る。

## 本文

### 1. 調査の方法

コードを 3 つに分けて読んだ（実行時の制御の経路、上位層・安全フィルタ・知覚、データ生成と評価）。どれも file:line の根拠つき。区分:
- **不可能**: 実行時の制御の判断にシミュレーションの真値を使う（実機では得られない）
- **既知の仮定**: 固定物の位置・寸法やカメラの較正を、誤差のない既知として扱う
- **理想化**: 実機でも近いことはできるが、雑音・遅延・ばらつきがない
- **生成・評価のみ**: データ生成・失敗注入・成否判定・記録で真値を使う（制御には効かない）

### 3. データ生成・評価（制御には効かない。ただし「実機でも同じ作り方で作れる」という主張に関わる）

| 項目 | 真値・シミュレーション専用の操作 | 実機での代替 |
|---|---|---|
| 場面のリセット | 腕と立方体の状態を直接書き込む（瞬間移動）。失敗した試みは同じ配置で作り直す | 人手、または自動の置き直しの仕組みが要る。完全に同じ初期状態は不可能 |
| エキスパートの動作段階と位置合わせ | 立方体の真の位置・速度・指先の中心で段階を判定し、1 mm 以内に合わせる | 立方体の 6 自由度の追跡（mm 精度）が要る |
| 失敗注入の発動・確定・着地の検査 | 把持中か、箱までの距離、立方体の上がり・速度・傾き・隙間を真値で判定 | 知覚で置き換え可能だが難しい（傾きの推定など） |
| R2 の失敗検出と引き継ぎ | 失敗の検出器に真値を渡す。同じ状態の保存と復元（決定性のため） | 知覚による検出が要る。状態の復元は実機にない |
| 成否と保存の可否 | 真値の位置と速さで判定 | 知覚か人の確認 |
| 評価の失敗注入（P1〜P3）の成立の判定、成功の判定、接触の計数 | 真値と MuJoCo の接触の一覧 | 実験の道具（評価専用）。接触の計数は実機では力覚・触覚か人の注釈 |

→ 説明資料と README の「実機でも同じ作り方で復帰データを作れる見込み」は、**立方体の姿勢の推定とリセットの仕組みが前提**であることを書き足す必要がある。

### 4. 改修の案（「知覚のみの実行系」、決裁の指示どおり箱も知覚する）

**4-1. 疑似 RGB-D（RealSense 相当）**
- 俯瞰カメラと手首カメラについて、今と同じ位置・画角で深度を描く（MuJoCo の深度描画）。RealSense は深度をカラーに位置合わせして出すので、**方策の RGB 入力は変えない**（再学習しない）
- 俯瞰は作業域まで約 1.3 m なので D435 相当、手首は対象まで 10〜30 cm なので D405 相当とし、公称の仕様から距離に応じた雑音・量子化・縁の欠損・最小距離以下の欠損を足す。値は実装の前に固定する

**4-2. 知覚（毎読み取り、30 Hz 相当に間引く）**
- 深度から点群（カメラの較正と手首カメラの順運動学）→ テーブル面の除去 → ロボット自身の除去（関節角と形状モデルで描いたマスク。実機でも運動学でできる）
- **箱**: 黄色の色と深度から箱の点を取り出し、既知の寸法の直方体を当てはめて位置と向きを推定する（真値は使わない）
- **立方体**: 残りの点をまとまりに分け、RGB の色で色を付ける。「箱の中か」は推定した箱の内側にあるかで判定
- 隠れの対策: 立方体と箱は触れない限り動かないので、過去の観測を一定時間保持する（占有の地図）

**4-3. 置き換えるもの**
- 安全フィルタ: 障害物を「知覚した目標以外の立方体（テーブル上）」と「知覚した箱の壁」にし、手・指の形状と点群（または当てはめた形）の最短距離で制約を作る。二次計画の本体は変えない。深度の誤差に合わせて余裕を見直す（検証用のシードだけで決める）
- 完了判定・手首カメラの箱の領域・俯瞰の箱の領域: 設定の箱の位置ではなく、知覚した箱の位置を使う
- 完了判定の「グリッパが開」: 制御器の旗ではなく、指の関節から測った開き幅を使う
- 真値の漏れの経路: 方策に渡す観測（センサの値）と記録用の真値を別の入れ物に分け、方策の入口に真値が届かないことを検査で確かめる

**4-4. 変えないもの（理由つきで限界に書く）**
- 方策（再学習しない）: 画像の雑音・照明のランダム化や指の状態の変更は再学習が要り、今の評価全体の作り直しになる
- 推論中の物理の停止と一定の遅延: 実行系の時間の模擬は今のまま。任意で、遅延を測った分布から毎回引く追加の検査を足せる
- データ生成・評価の真値: 生成と評価の道具なのでそのまま。主張の書き方を直す（3 の →）

**4-5. 評価の扱い**
- 今の最終評価（真値の安全フィルタ）は主の結果としてそのまま残す。知覚のみの実行系は「結果を見た後に加えた改修」として、未使用のシード範囲（最終評価用の 120000〜 のうち未使用のところ）で新たに評価する。閾値・余裕は検証用のシードだけで決める
- 候補（回す前に固める）: 最終モデルで、失敗注入なし 99 試行・P1〜P3 各 50 試行を「真値のフィルタ」「知覚のフィルタ」「フィルタなし」で同じシードの対にし、主な見方は失敗注入なしの接触の有無と成功率、副次で P1〜P3 の復帰。3 個の連続タスク 20 回を知覚の実行系で。知覚そのものの精度（立方体・箱の位置の誤差、箱の中の判定の一致率）も測る
- 計算量の見込み: GPU で 4〜6 時間（深度の描画と点群の処理が加わる）

**4-6. 日程の見込み（締切 11/2）**
- 疑似 RGB-D と雑音の模擬: 1〜2 日
- 知覚（点群・自己除去・箱の当てはめ・立方体のまとまり・占有の地図）と検査: 3〜4 日
- 安全フィルタ・完了判定・グリッパの開き幅・観測の分離の置き換えと検査: 2 日
- 検証用のシードでの余裕・閾値の決定: 1 日
- 評価: 1 日
- 説明資料・README・動画の更新: 1〜2 日
- 合計 9〜12 日程度
