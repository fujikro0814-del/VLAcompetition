## 本文

### 1. 指令の口と作動の模型（0108 の 2 の 2・3）

- **実行系の側**（`runtime/motion.py`）: 行動の手先の速さ → x_cmd の積分（旧版と同じ）→ 追従器と IK（旧版の TeleopControllerIK をロボットだけの模型で使う）→ 制限層（libfranka の limitRate と同じ式、G3 の値 × 0.99、1 kHz）→ 関節の位置の指令
  - IK は**指令の姿勢**（制限層の出力）の上で解く。測った関節角は綱（0.10 rad）にだけ使う。理由は 4
  - 試行の始めは、ロボットが報告する最後の指令（libfranka の q_d）から続ける（指令の跳びを作らない）
- **世界の側**（`harness/world.py`）: 関節の位置のサーボ（旧版と同じ利得）に重力の補償を作動器を通して足し（実機の内部の制御器と同じ）、関節の力を 87・12 Nm で切る
- **ハンド**（`harness/hand.py`）: move(幅, 速さ)・grasp(幅, 速さ, 力, 許容幅)、開き幅と is_grasped を報告
  - 腱の速度のサーボに力の上限を付けた形にし、指の速さは指令の速さ、力は上限で決まる
  - 上限（開き幅 0.1 m/s、指 1 本 70 N）を超える指令は拒む
- **把持力の確かめ**（学習用 59000〜59009、エキスパート 10 本、`docs/results/hand_check.json`）

| 項目 | 結果 |
|---|---|
| 成功 | 30・40・70 N で、どれも 10/10 |
| めり込み | 0.36 mm 以下 |
| 握っている間の滑り | 1.0 mm 以下 |
| 指の速さ | 0.041 m/s 以下 |
| 握った開き幅 | 3.9 cm |

  - 決めた値: **把持力 40 N/本**、開き幅の速さ 0.08 m/s、指の当て板の接触 30000 N/m・600 N·s/m、握る力の立ち上げ 0.2 s
  - 当て板の減衰 300 や立ち上げ 0.05 s では、握った瞬間の接触の揺れで腕のサーボの力の変化が 1000 Nm/s の 6.7 倍になった。上の値で 0.7 倍
- **G3 の監査**（`harness/audit.py`）: 口を通る指令にかける
  - 関節の速度・加速度・躍度（1 kHz の差分）
  - 手先の並進（指令の順運動学）
  - ハンドの速さ・力
  - 参考として、位置のサーボの力とその変化も記録する（指令ではないが、上の設定で上限の中）

### 2. センサの模型（0108 の 2 の 1・6）

- 手首は 848×480・縦 58° で描き、中央の 480×480（58°×58°）を切り出して 256 に縮める。俯瞰は色 90°×65° の中央 45°（520 px）を 256 に縮める
- 30 fps で撮り、撮った時刻の状態を控える。描画と雑音は、実行系が画像を読むこまだけに遅れて作る。雑音はこまの番号から引くので、描く順によらない
- 描画の費用: 深度 848×480 で 1 枚約 3.2 ms
- 推論の時間 L_inf（0108 の 2 の 6）: Step J の記録の wall_s は、観測を組む前処理（`builder.build` の前から時計を始める）と推論の両方を含んでいた。そのまま分布にした（`configs/latency_v1.json`、各組のプロセスの最初の 1 回を除く）

### 4. 段階 1 の旧モデル（R2）の、v2 の実行系での振る舞い（組み立ての診断。学習用 59050〜59054、失敗注入なし 15 試行）

| 条件 | 成功 |
|---|---|
| 旧版の経路（41_results.py、安全フィルタ切） | **15/15** |
| v2（センサの模型・制限層・指令の姿勢で解く IK・重力の補償） | **3/15** |
| v2 で制限層を外す | 2/15 |
| v2 でセンサの要素（色の雑音・58°・遅延・較正誤差）を外す（3 試行だけ） | 0/3 |
| v2 で重力の補償を外す | 4/15 |
| v2 で IK を測った関節角で解く（旧版の作り） | 8/15 |
| 上に加えて重力の補償も外す | 8/15（センサも理想にすると 10/15） |

- 主な原因は、センサではなく**腕の動きの作り**（IK を指令の姿勢で解くか、測った関節角で解くか）
- ところが、IK を測った関節角で解く作りは、制限層と組むと加速度の上限による遅れがサーボの遅れと重なる
  - その結果、エキスパートでも 20 本中 6 本が振動して時間切れになった
  - 関節の加速度は上限の 70 倍（関節の可動域の端でも切り詰めるため）
- 指令の姿勢で解く作りは、エキスパートで 20/20・違反 0 で、制限層（0107 の 8-2 の「IK は次の手の出発点に制限層の出力を使う」）の考えにも合う。**こちらを本線にする**
- つまり、段階 1 の旧モデルは、作動の上限を守る腕（とその制御の作り）では大きく落ちる
  - 目標書の段階 1 は「学習済みのモデルはそのまま」なので、この落ち方を結果として報告する
  - 段階 2（同じ作動の模型で作り直して学習し直す）がこの差を埋めるかが見どころになる
- 旧版の経路と v2 の差には、ほかにハンドの速さ（閉じるのに 0.5 s）・推論の結果が届く時刻などの効きも残っている（重力の補償・IK を旧版に戻し、センサを理想にしても 10/15）
  - 最終評価の結果の解釈のために、部品の寄与を E11（参考）として分けて示す案を、日程に余裕があれば出す
