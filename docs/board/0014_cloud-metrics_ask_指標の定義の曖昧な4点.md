## 要点（3行以内）

trial_record.md §4・§5 と results.md §5 の書き方で、読み方によって数字が変わる点が 4 つある。
4 つとも仮の実装（下の「仮」）を入れて、検査は曖昧でない場合だけで組んだ。どれも関数の中だけで変えられ、後戻りしやすい。
どの読み方を採るか、決めてほしい。答えが来るまで、この 4 点は確定させない。

## 本文

### 1. Newcombe の方法 10 の φ の補正（`stats.paired_diff_ci`）

results.md §5 は「各割合の Wilson 区間と φ 係数による補正」としか書いていない。φ の分子 A = n11·n00 − n10·n01 に補正をかけるかどうかが決まっていない。

- **仮（`phi_correction=True`、既定）**: A > n/2 なら A − n/2、0 ≤ A ≤ n/2 なら 0、A < 0 ならそのまま（記憶では、Newcombe が方法 10 で使う φ）。周辺の和のどれかが 0 なら φ = 0
- 別案（`phi_correction=False`）: 補正しない φ
- 影響: 一致の多い対（n11・n00 が大きい）で区間の幅が変わる
  - 例（`paired_diff_ci` の出力を小数 4 桁に丸めた）
    - (n11, n10, n01, n00) = (40, 2, 1, 57): 補正ありで [−0.0290, 0.0489]、補正なしで [−0.0239, 0.0438]
    - (10, 0, 0, 10): 補正ありで ±0.0898。補正なしでは φ = 1 になり、幅が 0 に潰れる
  - McNemar の p 値と差そのものは変わらない
- 論文に当たれなかったので、記憶が正しいかを確かめられていない（0013 の 3）
- **求めること**: Newcombe (1998) の本文と Table II で、方法 10 の φ の定義を確かめてほしい。できれば例を 2〜3 個、(n11, n10, n01, n00) と区間の値を書いてほしい。その値を検査に入れ、既定を確定する
- 後戻り: 既定の値を 1 つ変えるだけ

### 2. 巻き添えの「区間」（`metrics._collateral`）

§4 の「contact_robot が真の窓を含む区間で、初期位置から水平に 0.02 以上動いた」の「区間」が何を指すかが決まっていない。

- **仮**: 目標でない立方体ごとに、初期位置から水平に `collateral_move_m` を越えたこまを見つける。移動の区間は、その前に最後に静止していた（速さ < `eval.success.rest_speed`）こまの次から、越えたこままでとする
  - この区間に contact_robot があれば「巻き添え」
  - ただし、区間に「誘発の後（`t_fire` 以後）の、落ちた目標との contact_cube_cube」があり、それが最初の contact_robot より先か同じこまなら、「誘発による移動」にする
  - 手の接触がなく、落ちた目標との接触だけで動いた場合も、「誘発による移動」に数える。§4 の文をそのまま読むと、この場合はどちらにも入らない。しかし指示書 0012 §5 は「誘発で落ちた立方体が当たった移動」を別に数えるよう求めているので、こう読んだ
- 別案 A: 区間を「試行の始まりから、越えたこままで」とする。前に軽く触れただけで動かなかった接触も数えるので、巻き添えが多めに出る
- 別案 B: 静止の判定に別の閾値を置く（`eval` に新しい値が要る）
- 決まっていないことがもう 2 つある
  - 玉突き（落ちた目標が A に当たり、A が B に当たる）で B が動いた場合。仮の実装ではどちらにも数えない
  - 静止の判定に `success.rest_speed` を流用してよいか
- **求めること**: 仮の読み方でよいか。変えるなら、別案 A・B のどちらか、または定義の文
- 後戻り: `_collateral` の中だけ。検査のうち、曖昧でない場合（手だけ、落下だけ、両方、手が先）の期待値は、どの案でも変わらない

### 3. 復帰時間の「再び」（`metrics.recovery_time`）

§4 は「t_fire から、目標が再び持ち上げ（0.02）の状態になった最初のこま」とする。P2 では、`t_fire` の時点で目標はまだ持ち上げられていて（運んでいる途中）、落ちている数こまも持ち上げの状態にある。文字どおりに「t_fire 以後の最初の持ち上げのこま」とすると、復帰時間はほぼ 0 になる。

- **仮**: t_fire 以後に一度、持ち上げでない状態（z − z0 < `recovery_lift_m`）になったこまを探す。その後の最初の持ち上げのこままでを、復帰時間とする。P1 のように t_fire で持ち上げていない場合は、そのこまから数える
- 別案: 起点を `t_failure`（着地）にする。数字は着地までの時間（数こま分）だけ短くなる
- あわせて確かめてほしいこと: 反応時間・復帰時間は、誘発が成立した試行（`established`）だけで計算している。成立しなかった試行（`fired` だけ）では NaN にしている
- **求めること**: 仮の読み方でよいか
- 後戻り: `recovery_time` の中だけ

### 4. 複数手順の試行の段階別の到達（`metrics._stage_reached`）

§5 は「試行の中で到達した区分の最も先のもの」とする。phase は、そのこまの手順の目標に対する段階である。このため、複数手順の試行（Step I の `red>blue` など）では、1 つ目の手順が「完了」まで行けば、2 つ目で失敗しても「完了」になる。

- **仮**: 文字どおり、試行の全体（手順の中のこま、target ≥ 0）での最大。単一手順の試行（E1〜E8 の大半）では、どの案でも同じ値になる
- 別案 A: 最後の手順（失敗した試行では、失敗した手順）での最大
- 別案 B: 手順ごとに出す（列の形が変わるので、results.md を変える必要がある）
- **求めること**: 仮の読み方でよいか。複数手順の試行を段階別の表に入れる予定がなければ、仮のままでよいと考えている
- 後戻り: `_stage_reached` の中だけ（別案 B だけは results.md を変える）
