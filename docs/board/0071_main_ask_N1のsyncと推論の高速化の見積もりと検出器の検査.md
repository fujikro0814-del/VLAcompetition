## 要点（3行以内）

(1) 遅れのない実行（sync）では **A の復帰データははっきり効く**（P1: 同じ種の 24 対で R1 15・N1 2、McNemar p = 0.001）。C は差がはっきりしない（P3: 28 対で 14 と 10、p = 0.42）。
(2) d を下げられるのは**出力を変える手（流れの積分の刻み数）だけ**: 刻み 8 → d=4、5 → d=3、3 → d=2。出力を変えない手（コンパイル）はこの環境では逆に遅い。基準（今の推論）を固定入力で回し直すと p95 0.41〜0.42 s で、決まりでは d=5 になる（d=4 は境目）。
(3) 失敗の検出は、成功した試行で**掴み損ね (i) が R1 11/96・N1 12/96 で誤発火**（閉じてから 2 cm 持ち上がるまで最大 2.45 s。窓 2.0 s が短い）。(iii)(iv) は 0。閾値は変えずに諮る。R2 の実装は小さな試しで検査 (a)(b) と変換が通った。

### 2. 0070 の 2 の (2): 推論を速めて遅れ d を下げる手の見積もり（採用はしない）

**測り方**（`scripts/44_speed.py`、`outputs/speed/bench.json`）: R1 の 3 万手を評価の設定で Step G の検査の帯 198700〜198709 に走らせ、最初の 1 回を除いた推論の入力 100 組（前処理の後の入力・雑音・前の塊の残り。91 組は前の塊の残りあり＝RTC の誘導あり）を保存した。各案を同じ 100 組に 3 回ずつ当てて、方策の推論の実時間（`torch.cuda.synchronize` 込み）の p95 に、前処理の平均 3.8 ms を足して、決まり（p95 ÷ 0.1 s の切り上げ）で d を出した。塊の差は、保存したときの今の推論の出力との差（同じ入力・同じ雑音）。GPU はほかに何も回していない。

- **d を下げられるのは刻み数を減らす手だけ**。ほかの手は速さがほとんど変わらない（5% 以内）
- 刻み数を減らすと出力が変わる。1 手の手先の差分の差は平均 0.02〜0.16 mm だが、最大は 1.7〜9.7 mm、グリッパの符号が変わる手もある。**閉ループの成功・立ち直りへの効きはこの見積もりでは分からない**（採るなら、その刻み数で自然・P1〜P3 を回して確かめる必要がある）。学習は刻み数 10 のまま
- コンパイル: triton がないので inductor（コードを生成して速くする既定の方法）は使えない。triton-windows を入れるのは環境の追加で承認が要るので入れていない。triton なしで使える cudagraphs は出力は同じだが、RTC の誘導が逆伝播を使うため CUDA グラフの速い経路に乗らず、**約 3 倍遅い**（10 組だけで測った。100 組 × 3 回は 15 分を超えても終わらなかったので止めた）
- 推論の時間の大半は、刻みごとの行動の専門家の計算と、RTC の誘導の逆伝播（前の塊の残りがある推論だけ）。平均は刻み数にほぼ比例し（10・8・5・3 で 302・247・178・100 ms、1 刻み約 29 ms）、画像と言語の前処理の部分は十数 ms と読める
- **基準の p95 は 0.41〜0.42 s で、決まりでは d=5**。d を決めた閉ループの測定（0066、p95 0.396 s）は境目のすぐ下で、同じ推論でも測り方と回によって 4 と 5 をまたぐ（0066 の 899 回でも 0.423 s）。d は 0068 のとおり 4 のまま

### 3. 0070 の 5 (b): 失敗の検出の、成功した試行での誤発火（`outputs/results/G2diag/failure_detect_check.json`）

G2 の自然で成功した試行（R1 96・N1 96）に (i)〜(iv) を当て、成功の時刻より前に発火したものを数えた（`src/recovla/eval/failure_detect.py`、閾値は `configs/default.yaml` の `eval.failure_detect`、案のまま）。

| | R1（96） | N1（96） |
|---|---|---|
| (i) 掴み損ね | **11** | **12** |
| (ii) 落下（机の上） | 0 | 0 |
| (ii) その他の落下（0070 の 5 (a)） | 0 | **1** |
| (iii) 誤った色へ接近 | 0 | 0 |
| (iv) 停滞 | 0 | 0 |

- **(iii)・(iv) は成功した試行で発火しない**ことを確かめた
- **(i) の誤発火の原因**: 成功した掴みでも、閉じてから目標が 2 cm 持ち上がるまでの時間は中央値 1.3〜1.4 s、90 百分位 2.05〜2.1 s、最大 2.45 s。窓 2.0 s を超えてから持ち上がった掴みが「掴み損ね」になった（誤発火した 23 本はどれも最初の掴みで発火し、その掴みは閉じてから 2.05〜2.45 s で持ち上がっている）。方策は閉じた後、指が止まるのを待ってからゆっくり持ち上げる
- **(ii) その他の落下の 1 件**（N1、194079）: 目標が箱の縁（高さ 7.1 cm）で 0.3 s 止まり、そのあと箱に入って成功した
- **閾値は変えていない**（0070 の 5 (b)）。案: (i) の窓を 2.0 s → **3.0 s**（成功した掴みの最大 2.45 s に余裕）、(ii) その他の落下は静止の時間を 0.3 s → **1.0 s**（成功の判定と同じ長さ）。どちらも承認の後に同じ検査をやり直す
- **P1 の成立の条件にも同じ「2 s」がある**（誘発の定義、6f6d2bc で固定）。P1 の成立のうち「ずらした後も最初の掴みのまま 2 s より後に持ち上がった」（本当は掴めていた）ものを数えると、各条件で 0〜1 本（R1 の評価の設定 0/25、範囲 10 1/26、naive 1/29、sync 1/29、N1 sync 0/24、完了条件 4 0/18）。数字への影響は小さい。誘発の定義は変えない
- 分類（自然な失敗 6 本の失敗直後の状態）は、(b) を通ってから計算する（まだ計算していない）
