**4 工夫した点（数字はどれもテスト用の値）**
1. 復帰デモの自動生成: スクリプト化したエキスパートが集めた成功例に、失敗を注入してからエキスパートが立て直す区間を足した（人手なし）。数字: 掴み損ね（P1）の復帰成功率、復帰デモありで学習したモデル（R1）対 なし（N1）が 非同期実行 44% 対 10%・同期実行 48% 対 5%（どちらも Holm 補正後 p < 0.01）
2. 推論遅延と RTC の取引: 推論遅延（4 ステップ＝0.4 s）を隠す RTC はチャンク境界での速度の不連続を 0.038 → 0.011 m/s に減らすが、P1 の復帰成功率は 49% → 0%。滑らかさより復帰を取り、RTC を使わない非同期実行（naive）にした。図 3
3. 安全フィルタ: 参照位置の速度を、障害物（目標外の立方体・箱の壁）との距離の不等式で絞る。失敗注入なしの接触 17/99 → 5/99。代償に、隣の立方体への接近を止め続けて失敗した試行が 2 本（フィルタなしでは触れながら成功）
4. 目標位置のキュー: 指示文だけでは色を見分けられなかったので、俯瞰カメラの色の検出から目標の位置を方策の入力に足した。指示と目標位置のキューを一緒に差し替えたとき、指示した色に向かった割合 99/99
5. LLM による分解・完了判定・姿勢を立て直す再試行: Claude Haiku 4.5 が日本語の指示をサブタスクに分け（30 文中 29 文が期待どおり）、俯瞰と手首のカメラで完了を判定し、30 s で終わらなければ手を待機位置へ戻して再試行する。3 個の連続タスクで 10/20、再試行で完了したサブタスク 9。戻す動きの前後の比較（結果を見た後に加えた比較）では 11/20 → 10/20 で、3 個とも入る数は増えなかった
