## 要点（3行以内）

N1 の完了（22:50 ごろ）の後に回す手順の決まりの案。遅れ d は R1 の 3 万手で RTC ありの推論を 100 回測って `delay_rule` を当てる。RTC の設定は 2×2 を P2 各 30 回、最良から 3 回以内の組に絞り、継ぎ目の跳び → 反応時間の順に見る。

### 1. 遅れ d の測定（手順書 Step G の 1、`runtime.delay_rule`、`41_results.py dcal`）

### 2. RTC の設定の決定（手順書 Step G の 7）

| 項目 | 案 |
|---|---|
| モデル | R1 の 30000 手の保存点 |
| 組 | `rtc_guidance_horizon`（範囲 E）∈ {10, 40} × `rtc_schedule` ∈ {LINEAR, EXP} の 4 組。重みの上限は 10 のまま。s = 10、d は 1 で決めた値 |
| 試行 | 各組 **P2 誘発 30 回**、4 組とも同じ種（下の 4）。配置は種の乱数列のまま（0055 の 5） |
| 手順 1: 成功の足切り | 各組の成功数を数え、**最良の組の成功数から 3 回以内**（30 回中。約 10 ポイント）の組だけを残す |
| 手順 2: 継ぎ目の跳び | 残った組の中で、**継ぎ目の跳び**（`seam_jump_mean` の試行ごとの値の中央値、全 30 回）が最も小さい組を選ぶ。ただし最小との差が **最小の値の 10% 以内** の組は「同じ」とみなして手順 3 へ |
| 手順 3: 反応時間 | 同じとみなした組の中で、**反応時間**（`reaction_time_s` の中央値、P2 が成立した試行だけ）が最も小さい組 |
| 手順 4: 同点 | それでも決まらなければ、今の既定（範囲 10・指数）に近い方（範囲 10 を優先、次に指数を優先） |
| 順位の理由 | 手順書が「継ぎ目の跳びと反応時間から決める（成功率が大きく落ちない組）」としており、RTC の目的は塊のつなぎの滑らかさなので跳びを先にする。反応時間は成立した試行だけで数が少なくなるため後にする |
| 記録 | `outputs/results/RTC2x2/`（4 組の表、対の比較、図）。決めた組を `runtime.rtc_guidance_horizon`・`rtc_schedule` に書く |
