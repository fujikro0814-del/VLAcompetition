## 要点（3行以内）

知覚を実装し、学習用のシードで閾値を決めた: 自己除去の太らせ方 0、テーブル面から 1.5 cm、安全フィルタの余裕 27.4 mm（立方体の位置の誤差の p95）、知覚の遅れ 0.12 s。
回す前に決めた「ロボットの点が残る割合 ≤ 0.5%」の決まりは太らせ方 3 cm を選び、手首の立方体の検出を 28% に落とすので採らなかった（下の 2）。起動時の箱のずれの閾値も、0107 の 2 cm では 20 本中 5 本が止まるので広げた（下の 4）。
v2 の実行系（知覚・安全フィルタ・制限層・世界を止めない時間・センサの模型）は通しで動く。

## 本文

### 1. 知覚の作り（0107 の 4 のとおり、1 点を変えた）

- テーブル面からの高さは、**そのカメラ自身の深度から当てはめた平面で測る**（俯瞰は起動時に当てはめて保つ、手首はこまごと）
  - 信じているテーブル面で測ると、俯瞰では較正誤差（回転 0.5°）と深度の系統のずれで机が傾いて見える
  - その結果、5 mm の閾値で机の点の 86%、25 mm でも 0.4% が机より上に残った
  - 自分の深度の平面なら、同じ誤差が机と物に同じように効くので打ち消される
- 起動時の確かめ（テーブル面と、信じている値とのずれ）は、この当てはめで行う

### 2. 自己除去の太らせ方とテーブル面からの閾値（0108 の 2 の 4・5、`docs/results/perception_thresholds_v1.json`）

学習用 59100〜59109、エキスパート 10 本、こま 311（0.5 s ごと）。真のカメラの分割と照らした。M = 太らせ方、H = テーブル面からの閾値（1.5 cm）。

| 量 | 俯瞰 | 手首 |
|---|---|---|
| ロボットの点が残る割合（M = 0 → 1 cm → 3 cm） | 7.8% → 1.2% → 0% | 20.8% → 4.9% → 1.0% |
| 太らせすぎて立方体の点を消す割合（M = 0 → 1 cm → 3 cm） | 4.7% → 12.7% → 21.7% | 9.3% → 45% → 81% |
| 立方体の検出（上面が見えるもの、M = 0 → 3 cm） | 92% → 75% | 75% → 27% |
| 取り違え（M = 0） | 8.0% | 5.8% |

- 手首でロボットの点が多く残るのは、hand-eye の較正誤差（3 mm・0.5°）で、10 cm 先の指の描画が十数画素ずれるため
- **回す前に置いた決まり**（ロボットの点が残る割合 ≤ 0.5% の最小）では、**M = 3 cm** になる。手首の立方体の点の 81% を消し、検出が 27% に落ちる
- この知覚は立方体を**色で**拾う（灰色・黒のロボットの点は立方体にならない）。安全フィルタの障害物も、生の点ではなく当てはめた立方体と箱の壁
  - つまり、ロボットの点が残っても知覚の出力は悪くならない
- そこで、知覚の出力で決めた: **M = 0、H = 1.5 cm**（検出から取り違えを引いた値が、俯瞰と手首の悪い方で最もよい組）
- H の決まり（最初は「机の点が H より上に残る割合 ≤ 0.1%、立方体の画素が H 以下で落ちる割合 ≤ 10%」）も、試しの 1 本で意味がないと分かり、本番の前に直した
  - 俯瞰の机の点は、縁の空飛ぶ画素のために H を上げても 0.13% で止まる
  - 立方体の側面の下の方は、H によらず落ちる
- 経緯はスクリプトの説明と `configs/runtime_v2.yaml` に書いた

### 3. 知覚の精度と計算時間（`docs/results/perception_accuracy_v1.json`、学習用 59200〜59219、エキスパート 20 本、10 Hz の更新 3,096 回）

| 項目 | 値 |
|---|---|
| 机上の立方体の中心の位置の誤差（3 次元） | 中央値 13.9 mm、p95 27.4 mm |
| 立方体が見つからない更新 | 0% |
| 箱の中かの判定と真値の一致 | 93.6% |
| 箱の推定の位置の誤差 | 20 本で最大 30 mm、中央値 約 13 mm。向きは最大 0.95° |
| 更新の計算時間 | 中央値 0.106 s、p99 0.114 s |

- 誤差の大半は俯瞰の較正誤差（0109 で控えめに置いた回転 0.5° は、1.3 m で約 1 cm）による
- **安全フィルタの余裕**（0107 の 5 の決まりどおり）: p95 の **27.4 mm** を足す（d_min 30.4 mm、検出の距離 57.4 mm）。主系に残すかは、検証用 199800〜 の 3 ポイントの決まりで判定する
- **知覚の遅れ**（0107 の 4-2）: p99 を 10 ms 単位で切り上げて **0.12 s**
- 箱の中かの判定の不一致（6.4%）は、主に運んでいる・置いている途中の境目。完了判定は別に照合データで評価する（E7）

### 4. 知覚の失敗の止まり方の閾値（0107 の 4-4 の初期値を、学習用のシードで直した）

| 項目 | 0107 の初期値 | 学習用で見た最大 | 決めた値（最大の 2 倍） |
|---|---|---|---|
| 起動時のテーブル面のずれ | 5 mm・1° | 23.4 mm・1.24°（30 本） | 47 mm・2.49° |

- 決めた値は、「較正の大きな狂い」だけを止める値

### 5. G3（直交座標）

- 関節の上限だけでは、方策の動きで手先の並進の加速度が上限の 1.16 倍になった（R2、学習用 59050）
- 0107 の 8-2 の予定どおり、直交座標の上限を足した
  - 候補の指令の手先の速度・加速度・躍度が上限を超えるときは、その刻みの躍度の項だけを二分法で縮める
  - こうすると関節の上限も保たれる
- 監査は、口を通る指令の項目（関節・手先・ハンド）だけを違反に数える。位置のサーボの力とその変化は参考として別に書く（指令ではないため。0108 の 2 の 2）

### 6. 計算量の見込みの更新

- v2 の 1 試行の壁の時計は 25〜58 s（知覚の更新が 1 回 0.1 s、10 Hz）。旧版は約 10 s
- 最終評価 8 組（約 2,000 試行）は約 22 時間ぶんの計算で、3 本同時で 7〜8 時間の見込み
- 知覚を速くする手（手首の点の間引き）は、精度を測り直さずに入れると決まりに触れるので、今は入れない
