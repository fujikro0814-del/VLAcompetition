## 要点（3行以内）

G2（R1 の 3 万手、rtc・s=10・d=4・範囲 40・指数）: 自然 99 回は **96/99（97.0%、区間 91.5〜99.0%）で基準 70% を満たす**。P2 は成立 40/50（80%）、**復帰 0/40（区間 0〜8.8%）で基準 50% に届かず、G2 は不合格**。接触率 3.0% で安全フィルタは作らない。
原因: **評価の P2 では、落ちる間も手が方策のまま箱へ進む**（成立の時点で手は立方体から 8.5 cm、グリッパは閉）。**データの B では台本が手を止めて待つ**（手は立方体の真上 1.0 cm、指は開）。P2 の 40/40 が B の範囲の外。0045 の食い違いの表に、私はこれを載せていなかった。
計画書では G2 不合格で R2・R1+ を発動する。ただし R2 を手順書の書き方のまま（自然な走らせ方）で集めると、R1 は自然にはほとんど落とさないので、P2 に当たる状態がほぼ入らない見込み。進め方を下の 1 で諮る。

### 2. P2 から復帰しない原因: 評価の P2 と復帰データ B の食い違い（新しく見つけた）

|---|---|---|---|

- **食い違いの中身**: データの注入 B（`recovla.expert.inject` の `_run_dropped`）は、開いた後に台本が**手を止めて**立方体の静止を待ち、そこから保存を始める。評価の誘発 P2（`recovla.eval.induce` の `_p2`）は指を開いたまま保つだけで、**手先は方策のまま**（着地まで約 0.6 s、その間も箱の方へ進む）。制御を返した時点で、方策は「運んでいる」つもりで閉じる行動を出す
- 0045 の食い違いの表では、P2 ↔ B の「成立・確定の条件」を「ほぼ同じ」とし、落ちる間の手の動きを載せていなかった。**私の見落とし**。誘発の定義（6f6d2bc で固定）は変えていない
- 方策に渡した手がかりは正しい（落とした後も真値との差は中央値 0〜7 mm、見失いなし）。映像では、落とした後も手は箱の上へ進み、箱の上で止まったまま目標へ戻らない（`docs/media/2026-09-26_G2/R1_P2_195000_frames.png`）
- P1（完了条件 4 で 11/18）と P3（12/19）は半分以上が戻るので、弱いのは P2 だけ
