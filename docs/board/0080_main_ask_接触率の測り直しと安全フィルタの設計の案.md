### 3. 安全フィルタの設計の案（実装の前。0079 の 2）

形は手順書 Step G の 4・計画書 §4.4 のとおり（制御バリア関数の離散形を、手先の並進 3 自由度に当てたもの）。未定だった値と、当てる範囲を案として出す。

| 項目 | 案 |
|---|---|
| 置く場所 | B_提案書の「制御ループと指令の入口」で決めた差し込み口（`VelocityCommandIntegrator` の `x_cmd += vel·dt` の直前、`command_filter(x_cmd, dx, data) -> dx`）。IK と流用元の制御は変えない |
| 制限するもの | 参照位置の増分 Δx（並進 3 つ）だけ。**グリッパの指令と手先の向きには触れない** |
| 障害物 | 接触の数え方と同じ組: 机上の目標外の立方体と、箱の壁 4 枚（`ContactMeter.obstacle_mask`）。目標の立方体・箱の中の立方体・机は対象外 |
| 距離 d と向き n | 接触の計測と同じ距離の模型（native CCD、`ContactMeter.distances`）で、手・指の全ての衝突形状との最短距離と最近点の組を取る。n は障害物から手へ向かう単位の向き |
| 手先の遅れの扱い（手順書の落とし穴 13） | 距離は実際の手・指で測るが、制限するのは参照位置。参照は手先より先に 5〜17 mm 進んでいる。そこで参照位置での距離を d_ref = d + n·(x_cmd − x_hand) と見積もって使う（参照が障害物側に先行していれば小さくなる）。大きな余裕の距離を足す代わりにこうする |
| 不等式 | 距離の減り方の制限 n·Δx ≥ −γ(d_ref − d_min)。d_ref < d_detect の障害物だけ。Δx を、この不等式を全部満たす最も近い Δx に置き換える（変数 3 つ・不等式は高々 7 本の二次計画。有効な組を数え上げて厳密に解く。外部の解法器は入れない） |
| 値 | **d_min = 3 mm、d_detect = 30 mm、γ = 0.85（configs の既定）**。d_min は、台本のデモ（R1 の 330 本）の最短距離の 1 パーセンタイル 5.2 mm より小さく取る（データの動きはほぼ妨げない）。d_detect は、γ の制限が効き始める距離より十分遠い値。壁は鉛直なので、n はほぼ水平になり、箱に置くときの縦の動きは制限しない |
| 計算の頻度 | 距離と n は指令を読むたび（10 物理手ごと、50 Hz）に測る。その間の物理手では、d_ref を n·(累積した Δx) で一次に見積もる。物理手ごと（500 Hz）に測るのは重いため（1 回で最大 7 列 × 手・指の形状の距離計算） |
| 当てる範囲 | **方策が指令を出している間だけ**。誘発が行動を上書きしている間（`induce_active`）と台本（データの生成）には当てない。誘発の定義（6f6d2bc で固定）と、生成済みのデータ（R1・N1・R2）を変えないため |
| 当てる評価 | 0079 の 2 のとおり、本線を使う全ての評価（R1・N1・R2・R1+、E1〜E3・E6〜E8、保存点の選択）に同じく当てる。本線の設定は「naive・d=4＋安全フィルタ」になる。E4（遅れと立ち直りの取引）は実行の方式の比較なので、全条件に同じくフィルタを当てる。**E5（計画書 §5）はフィルタの入と切の比較**として行う（計画書のとおり、接触率が 5% 以上になったので発動） |
| 記録 | 試行の記録の `safety_active`（こまごと、フィルタが指令を変えたか）と runtime の `safety_filter: true`（既にある欄）。変えた量の大きさ（‖Δx − Δx_cmd‖ の合計）も足す |

**検査（手順書 Step G の完了条件 7 に 1 つ足す）**
- (a) 合成の試験: 障害物（壁・立方体）へまっすぐ向かう参照を与えても、最短距離が d_min を割らない（許容 1 mm）。壁に沿う動きと離れる動きは変えない
- (b) 生成の種から 20 本を、フィルタを入れた実行器で作り直し、出力がフィルタなしと一致する（当てる範囲の外なので、一度も働かないことの確かめ）
- (c) 足す: 閉ループでの効き目の下見。naive＋フィルタで、今回と同じ `selection:194000:99`。接触率・成功数・`safety_active` の割合を、今回の 8/99・96/99 と種ごとに対で出す（選択用の帯。E5 の本番は最終評価用の種で行う）

**見込み**: 実装と単体の検査で 2〜3 時間、(c) は GPU で約 10 分。

**計画書・手順書との食い違い**: 手順書 Step G の 4 は「K1 または G2 で 5% 以上のとき」作るとしている。今回は本線の設定を naive に変えた後の測り直しで当たったので、変更一覧 v3 に日付つきで書く。
