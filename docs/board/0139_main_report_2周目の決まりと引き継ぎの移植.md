## 本文

### 1. 集めの決まり（案 3、`src/recovla/expert/handover_v2.py` の定数。集めの前に固定）

- 方策: 1 周目で採った R1v3・N1v3（2 万手）。実行のしかたは 0 周目の判断（naive・6 行、安全フィルタなし）で、評価（`82_v2_eval.py run`）と同じ組み立て。前半は記録しない
- 世界: v2 の設定に `configs/expert_v3.yaml` を重ねたもの（1 周目と同じ台本）。センサの模型・ハンド・G3 の監査は前半から後半まで同じ 1 つの世界
- 配置と目標: 種 s ごとに `scene.sample_layout(s)` と `choose_targets`（v1 の R2・P1 の評価と同じ決め方）。**R と N は同じ種の並び**（同じ配置・目標・ランダムな時刻）
- 引き継ぎ（生成の道具の側。真値を使う。実行系には入れない）。判定は行動の境目（10 Hz のこまの境目）で行い、引き継ぎの時点がそのまま記録の最初のこまになる
  - (i) 固まった: 開いていて、方策が塊を実行し始めた後、手（hand の原点）の速さ < 0.01 m/s が 0.3 s 続いた（0.01 m/s は台本が閉じる前に待つ速さ 0.005 m/s の 2 倍）
  - (ii) 方策が閉じる指令を出したとき、指先の中心と目標の中心の水平の差 > 15 mm、または手の高さ − 台本の把持の高さ（grasp_z）> 15 mm: その閉じる指令を開のままに替え（評価の道具の口 `action_filter`）、**次の境目（0.1 s 後）**で引き継ぐ
  - (iii) 種ごとに確率 0.3 で、U(1, 8) s のランダムな時刻（種だけから引く。R と N で同じ）
- 捨てる: 引き継ぐ前に成功・時間切れ（30 s）、引き継ぎの時点で閉じている、どれかの立方体が開始時から 10 mm 超動いた、台本が立て直せなかった（区分は v1 の R2 と同じ）、G1〜G3 の違反（G3 は前半・引き継ぎ・後半を通した世界の監査）
- 後半: 台本（引き継ぎの台本の種）が、実行系の Motion（x_cmd・追従器・IK・制限層の状態）とハンドをそのまま受け継いで立て直す。記録の形は v2 の生成と同じ（センサの値・信じている較正つき）
- 本数: R・N それぞれ 120。4 本同時（R・N を種の偶奇で 2 つずつに分け、各 60 に達するまで）。集めた区間は種の小さい順に 120 本を使う
  - 帯（44000〜44399）の終わりまでに片方が 120 に届かなければ、R・N とも少ない方の本数にそろえる（種の小さい順）。足りない分を別の帯から足すことはしない
- データ: R2v3 ＝ R1v3 のデータ（通常 240 ＋ 復帰 90）＋ 引き継ぎ 120（R1v3 から）。N2v3 ＝ N1v3 のデータ（通常 330）＋ 引き継ぎ 120（N1v3 から）。どちらも一から 2 万手（1 周目と同じ設定、fast_query）
- 報告に書くこと: N にも閉じる前に位置を直す区間が入ったこと。試みの数と捨てた理由を R・N に分けて

### 2. 採る・やめる基準（2 周目の検証。集めの前に固定し、以後は直さない）

検証: 自然 199330〜199362（99）、P1 199163〜199195（33）＋ 198120〜198185（66）。R1v3・N1v3・R2v3・N2v3 の 4 組を同じ種で、naive・6 行・フィルタなしで回す（R1v3・N1v3 はこの種では未評価なので回し直す）。

採る（すべて満たす）:
1. **自然の成功**: R2v3 − R1v3 ≥ +5（99 中）
2. **関所**: 8 組とも G1〜G3 の違反 0（`gate.require`）
3. **P1 が下がらない**: R2v3 の復帰／成立が R1v3 より 10 ポイント以上下がらない。かつ、両方で成立した対の「R だけ復帰 − N だけ復帰」（R2v3 対 N2v3）が、R1v3 対 N1v3 の値より 2 以上小さくならない
4. **仕組みの指標**: 自然の試行で、最初に閉じたこま（20 Hz の真値の記録）の時点で「指先の中心と目標の中心の水平の差 > 15 mm、または手の高さ − grasp_z > 15 mm」（1 の (ii) と同じ定義）だった試行の数が、R2v3 で R1v3 以下

やめる: 1 が届かない（下がった場合を含む）か、2・3・4 のどれかを満たさない → 引き継ぎの区間を外し、R1v3・N1v3 に戻す。3 周目（案 3 の繰り返し）は 2 周目を採ったときだけ回す。

記録するだけ（判定に使わない）: N2v3 − N1v3 の自然の成功、自然の試行での「固まった」状態（1 の (i) の定義）の割合、同じ試行で 1 の (i)〜(ii) が発火したはずの回数、McNemar の p。

[事実] 1 周目の R1v3 は自然 81/99（別の種）なので、+5 は 86 前後にあたる。99 対で +5 の検出力は低い（段階 3 の解析の見積もりで +5 pt は 0.14、`wf\x_power.json`）。採否は点の差で決め、有意性は報告するだけにする（0126 の共通の規則）。

### 3. v2 への移植と検査（学習に使わない 49030〜49035、R2 の帯の未使用の部分）

- 移植: v1 の `r2_collect.py`（世界を止める実行系・保存した状態からの復元）は残したまま、v2 用に `handover_v2.py` を新しく書いた。前半は評価の枠と同じ順（実行系の tick → 指令を世界へ → 物理の 1 手 → センサの模型）。引き継ぎでは世界を止めず、復元もしない（実行系の Motion をそのまま台本の口に渡す）
- スモーク（R1v3・N1v3 各 6 試み）: R 3 本・N 2 本を保存。捨てた理由は、掴んで運んだ後に立方体を落とした（立方体が動いた）6、引き継ぐ前に成功 1。保存した例: 49032（R）は方策が把持の高さで横に 10.8 mm ずれて固まり、台本が上がって近づき直して成功
- 変換と照合: 保存した 3 本を `convert --target-cue --cue-thresholds runtime_v2 --cue-without-flag` で変換し、`--verify` が PASS
- **ビット一致の検査（0069 の (b) にあたる）**: v2 の移植は保存した開始状態から復元しないので、保存した区間を回し直して確かめた。方策の推論（GPU）は回すたびに少し変わる（そのまま回し直すと、引き継ぎの時刻・理由・こま数は一致したが、最初のこまから手先が最大 0.9 mm 違った）ので、前半は記録した行動（行動の口に入った後の値）を同じ区切りで再生し、同じ物理の手で引き継いだ。**5 本すべてで、記録の真値の列（立方体の位置と姿勢・指先・x_des・物理の手ごとの x_des とグリッパの指令・開閉・段階）が全こまでビット一致**。センサの値（測った関節角・手先・開き幅）は雑音の乱数の消費の違いで最大 0.3 mm 違う。本番の後、同じ検査を R・N 各 5 本（計 10 区間）で行う
- G1・G2・G3: スモークの全試みで違反 0
- 所要: 1 試み 25〜50 s（保存したものは後半の台本を含めて 40〜50 s）。保存の割合はスモークで約 4 割。120 本に約 300 試み、4 本同時で約 1.5〜2 時間の見込み
