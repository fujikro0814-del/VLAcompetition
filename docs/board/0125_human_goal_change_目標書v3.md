## 本文（決裁の回答の原文）

目標書 v3 の追記（段階 2 の最終評価の結果を見る前に固める。決裁の承認による goal_change）

■ 変更の理由（変更履歴に書く）
- 決裁が、段階 2 で復帰が示せない場合に、現実的な実行系（G1〜G4 は不変）のまま改善を続けることを決めた。段階 2 の結果を見る前に決めたので、結果に合わせた変更ではない

■ 段階 2 の「失敗」の定義（次のどれか 1 つでも当たれば失敗）
- E3 ①（本線の R1v2 対 N1v2、P1 の復帰）が、Holm 補正の後で p < 0.05 にならない
- 最終モデルの P1 の復帰（E2）が 30% 未満
- 最終モデルの失敗注入なしの成功（E1）が 50% 未満

■ 段階 3（段階 2 が失敗したときだけ発動）
- 目的: G1〜G4 を満たす実行系のまま、復帰デモの効果（R 対 N）と復帰の能力を示す
- 許す改善の範囲（下の判断 2 で決める）:
  - データ: 本数を増やす、エキスパートの動きに乱れを加えた実演、方策を走らせてずれた状態からエキスパートに引き継ぐ区間（2 周目の作り方の一般化）
  - 実行の手段: 塊の実行の長さ、行動のならし方など
  - 学習の設定: ステップ数、画像の拡張など
- R と N の公正さ: 改善は R と N に同じだけ当てる。違いは「失敗注入からの復帰の区間を入れるかどうか」だけにする。方策を走らせて引き継ぐ区間を足す場合は、R と N の両方に同じ作り方で足し、そのことを書く
- 判断は学習用と検証用の種だけで行う。テスト用の種は最終評価の一度だけ
- 周回の上限 3 周。最後の学習を始めてよいのは 10/15 まで。最終評価は未使用のテスト用の種（140000〜）で一度だけ、10/20 までに終える
- 段階 3 の主要評価項目と基準は段階 2 と同じ（E1・E2・E3・E9 など）

■ 主な結果の決め方
- 段階 3 を発動し、その最終評価が 10/20 までに終われば段階 3 を主な結果とする。数字の良し悪しでは選ばない。段階 1・2 も並べて示す
- 10/20 までに終わらなければ、段階 2 を主な結果とし、段階 3 は途中経過として付録に書く
- 凍結 10/22、提出 10/31 は変えない
