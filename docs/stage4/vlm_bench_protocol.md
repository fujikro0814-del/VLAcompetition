## 3. 正解の決め方（`labels.py` の RULE、版 vlm-labels-v1）

閾値は `configs/default.yaml` の `eval.failure_detect`（自然な失敗の検出、0069・0070・0072）と同じ値を使う: grasp_window_s 3.0、lift_m 0.02、rest_speed 0.01、rest_hold_s 0.3、table_z_tol_m 0.01、held_dist_m 0.025、stall_hand_speed 0.01、stall_finger_speed 0.005、stall_s 3.0。

- **完了の判定の正解** = npz の `cube_in_box` が真 かつ 持たれていない（「持たれている」= `gripper_closed` かつ 指先の中心と立方体の中心が 0.025 m 未満）。描いたこまの値で決める。
- **掴み損ね**: グリッパが閉じたこまから 3.0 s 以内に、目標が 0.02 m 以上持ち上がらなかった。基準の時刻 = 閉じた時刻 + 1.5 s。
- **手を離れた出来事**: 「持たれている」区間で目標が 0.02 m 以上持ち上がり、その区間が終わったこま（基準の時刻）。その後 3.0 s 以内（次に持つまで）の最初の静止（`cube_linvel` の大きさ < 0.01 が 0.3 s）で行き先を決める。
  - 箱の中 → 成功
  - 机の上でない所（静止の高さが机の静止の高さ + 0.01 m 以上。箱の縁・壁の上・他の立方体の上）→ 置き損ね
  - 机の上で、手を離れた時に指が開いていない（閉じたまま滑り落ちた）→ 落とした
  - 机の上で、手を離れる前 0.5 s の指先の上下の速さが +0.02 m/s より上（上がりながら）→ 落とした
  - 机の上で、上下の速さが −0.05 m/s 以下（下りながら）か、直前 0.3 s の指先の水平の速さが 0.03 m/s 未満（止まって）→ 置き損ね
  - それ以外（運んでいる途中に開いた）→ 落とした
  - 静止が見つからない → 除外
- **止まった**: 指先の速さ < 0.01 m/s かつ 指の速さ < 0.005 m/s が 3.0 s 以上続き、その間ずっと目標が箱の中でない。始まりが 1.0 s より後。基準の時刻 = 始まり + 2.0 s。
- 成功の出来事が出たら、その試行のそれより後の出来事は使わない。
- **誘発の試行**（`induce.established` が真）: 誘発の時刻に合う出来事（P1: 閉じた時刻が `induce.info.t_closed` ± 0.3 s、P2: 手を離れた時刻が [`t_fire` − 0.3, `t_established`]、P3: [`t_fire`, `t_established`]）の正解を誘発の種類にする（P1 → 掴み損ね、P2 → 落とした、P3 → 置き損ね）。この出来事は同じ種類の数の上限より先に残す。
- 閾値の決め方の注記（結果を見る前、VLM に問う前）: 上下の速さ・水平の速さの閾値は、段階 3 の記録の誘発の試行で、P2（運ぶ高さ 約 0.15 m、上下の速さ ほぼ 0、水平 0.03〜0.19 m/s）と P3（下りながら 約 −0.1 m/s、高さ 約 0.09〜0.10 m で開く）が分かれるように決めた。この規則と誘発の種類の食い違いは 1 件（B P3 の試行 3: 閉じたまま滑り落ちた）、合う出来事が無いのは 3 件（A P2 の 31、A・B P3 の 28）。

| 視点 | カメラ | 大きさ | 処理 | 使い道 |


## 7. 採点（`score.py`。記述だけ）

- 完了の判定（モデル x 視点ごと）: 一致率（unsure・形の崩れた答えは外れに数え、率も別に出す）、取りこぼし（正解が真なのに yes でない）の率、誤検出 = 誤った完了（正解が偽なのに yes）の率、混同行列（正解 x yes・no・unsure・invalid）。実行器が決めた 69 点だけで、実行器と VLM の取りこぼし・誤った完了を並べる。取りこぼしの点（6 点。final.md の 4 本の場面だけの 5 点も）で VLM が yes と答えた数。
- 失敗の分類（モデル x 視点ごと、条件ごとも）: 一致率、種類ごとの再現率・適合率と件数、マクロ平均の再現率、混同行列（正解 5 x 答え 5＋invalid）、失敗と成功の 2 つに分けたときの一致率。
- 遅れ: 同期で呼んだ問いの `wall_s`（SDK の呼び出しの往復の秒）の中央値と 90 パーセンタイル。主の視点ごと・モデルごとに、項目 ID の SHA-256 の順で先頭 20 問を同期で呼ぶ（それ以外は Batch。Batch には 1 問ごとの時間が無いので、作ってから終わるまでの秒だけを記録する）。
- 費用: 1 問あたりの費用 = 実際の usage（入力・出力のトークン）x 料金表（per MTok、入力/出力: Haiku 5.5 $0.10/$0.50、Sonnet 5.5 $2/$10、Opus 5.5 $4/$20）、Batch は半額。トークンの中央値も出す。
- 拒否（`stop_reason` "refusal"）・形の崩れた答え・答えの無い問い（Batch の errored・expired）の数を出す。答えの無い問いは分母に入れない（数は書く）。
- 集計は独立な 2 つの実装（行ごとの数え上げと、配列・Counter での数え上げ）で行い、件数の一致を `dual_check` に書く（目標書_段階4.md 第 3 節 6 と同じ考え方）。

## 8. 除外の規則（結果を見る前に固定）

- 完了の判定: 時刻が記録の外（0 未満か、最後のこま + 0.1 s より後）、同じ手順で前の時刻と同じこまに寄った。
- 失敗の分類: 4 コマのどれかが記録の外、前に残した出来事の基準の時刻から 3 s 以内、同じ試行の同じ種類の 2 つ目以降（誘発の出来事は先に残す）、行き先の静止が見つからない、掴み損ねの判定の窓（閉じてから 3 s）が記録の外、規則と誘発の種類の食い違い、誘発に合う出来事が無い。
- 除外した項目は問わない（`items_*.json` に理由つきで残す）。問うた後に項目を除くことはしない。
