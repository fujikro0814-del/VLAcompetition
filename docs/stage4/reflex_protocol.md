# 握り損ねの反射（grasp-loss reflex）の手順

作った日: 10/11。ブランチ `s4-reflex`。実験はまだ回していない（第 8 節は提案）。

## 1. 考え方

運んでいる最中に立方体が落ちると、方策（SmolVLA）は元に戻れない。調べて分かった理由はこうだった。

- 方策は 50 行の塊を作り、6 行ごと（0.6 s ごと）に次の推論を始める。推論には約 0.3 s かかる。
- 落ちた後も、落ちる前の観測から作った古い塊が動き続ける。手は箱へ運び続け、空の指を閉じる。
- 落ちた後の観測から作った最初の塊が動くとき、手は立方体から約 13 cm 離れ、指は閉じている。これは学習のデータにない状態。
- 学習のデータの落下の実演は、「手が立方体の上で止まり、指が開いている」状態から始まる。

落下で手を止める診断（P2H、`src/recovla/diag/recovery.py` の FallHoldInducer）は、学習し直さずに復帰を 0/23 から 10/25 に上げた。
ただし P2H は、シミュレーションの真値（落ちた時刻・着地の時刻）を使っていた。

反射は、同じことを **ロボットが本当に持っている信号だけ** で行う。「実行をデータに合わせる」。カメラを使わないので、実機の Panda
（Franka Hand の開き幅）にも移せる。

## 2. 使う信号

| 信号 | シミュレーションでの出どころ | 実機での出どころ |
|---|---|---|
| ハンドの開き幅（2 本の指の和）とその時刻 | `GripperState.width`・`t`（10 Hz、雑音 0.1 mm） | libfranka の `GripperState.width`・`time` |
| 方策が出した開閉 | 行動の 7 番目（評価の道具が上書きする前） | 同じ |
| 手先の位置 | 測った関節角の順運動学 | `RobotState.q` の順運動学（`O_T_EE`） |
| 実行系の手先の参照 `x_cmd` | 実行系の内部の値 | 同じ |
| 画像の目標の手がかり（任意、既定は切） | 俯瞰カメラ | なし（実機にカメラがない） |

シミュレーションの真値（立方体の位置、接触、成否）は使わない。`src/recovla/runtime/reflex.py` は runtime の入れ物の中にあり、
`scripts/check_g1_boundary.py` の厳しい検査（違反 0）を通る（テスト `test_runtime_reflex_file_passes_g1_boundary`）。

## 3. 検出の決まり

ハンドの新しい読みが届くたびに 1 回判定する（行動の区切りの 10 Hz を待たない）。状態は「開いている → 閉じている途中 → 持っている → 発火」。

1. **持っている**: 方策が閉を出している間に、開き幅が持つ範囲 3.0〜6.0 cm に入り、前の読みとの差が 2 mm 以下の読みが 3 回以上・0.2 s 以上
   続き、閉じ始めてから手先が 3 cm 以上上がったら「持っている」とする。
2. **意図した放し**: 持っている間に方策が開を出したら、発火しない（最初に戻る）。
3. **落とした（主）**: 持っている間、方策が閉のままで、開き幅が基準より 4 mm 以上小さくなったら発火（`collapse`）。
   実機で落とすと grasp の指令は閉じ続けるので、開き幅は 0 へ向かう。基準は持ち始めの開き幅で、範囲の中の読みにゆっくり寄せる。
4. **落とした（副）**: 基準より 4 mm 以上大きくなったら発火（`open`）。段階 3 の P2 の誘発は指を開いて落とすので、シミュレーションでは
   こちらが働く。
5. **空掴み**: まだ持っていない間に、閉のまま開き幅が 2.5 cm 未満の状態が 0.3 s 続いたら発火（`miss`）。4 cm の立方体があれば、
   指はここまで閉じない。把持失敗（P1）で空を掴んだときがこれ。
6. 画像の手がかりが手先から離れたら発火する決まり（`cue_jump_m`）も作ったが、既定は切。持ち上げた立方体は俯瞰カメラで机の面に
   投影すると大きくずれるので、検証の記録で自然な試行の 76〜90% に誤発火した。

## 4. 発火の後にすること

出すのは、実機の口でそのまま出せる指令だけ（直交座標の参照と、ハンドの move）。

1. 古い塊と、計算中の推論を捨てる。
2. **止める**: 発火の時点で測った手先の位置へ、参照 `x_cmd` を戻して保つ（`stop=measured`、既定。速さの上限 0.25 m/s）。
   実機では「今の姿勢を保つ」にあたる。`stop=freeze` は参照をその場で止める（P2H と同じ形）。
   参照は腕より約 3.5 cm 先を走っているので、freeze だと手は落ちた所から約 4 cm 先で止まる（第 6 節）。
3. **開く**: 指を開く（ハンドの move。実機では grasp を stop してから move）。
4. **待つ**: 発火から 0.5 s たち、かつ開き幅が 7.5 cm 以上になるまで、推論を始めない（2.0 s で打ち切る）。
5. **やり直す**: 待ちの後は普通に推論を始める。腕は止まっているので、届いた塊は 0 行目から使う。塊を使い始めたら、検出は最初から数え直す。
6. 空掴み（`miss`）でも同じことをする（止める・開く・待つ・やり直す）。空を掴んだまま古い塊が手を持ち上げて箱へ運ぶのを止める。

記録: 試行の json の `"reflex"` に引数と事象（発火の時刻・理由・開き幅・基準・手先・捨てた塊・待ちの終わり・再開の時刻と塊）を残す。
run.json と resume_spec.json の `"reflex"` に引数を残す。反射が切なら、どの記録も前と同じ形。

## 6. オフラインの評価（記録の再生。シミュレーションは回していない）

記録から、実行系が持っている信号を作り直して検出器に通した（`ReflexParams` の既定）。開き幅は真の指の位置（20 Hz）を、ハンドの
センサの模型（頻度・遅れ・雑音・0.1 mm の丸め）に通した。誘発が行動を上書きしていた間の「方策の開閉」は記録に残っていないので、
落下（P2）と把持失敗（P1）は「閉のまま」とみなした（P2 では、発火のときに動いていた塊は全部、落ちる前の観測から作った塊だった）。
真値は、発火が本当の落下かを後で調べるのにだけ使った。

センサの模型（**仮定**。第 7 節）: `sim_v1`（10 Hz・遅れ 0・雑音 0.1 mm、今のシミュレーション）、`R10_L50_s05`（10 Hz・50 ms・0.5 mm、
実機の悲観的な見積もり）、`R30_L20_s05`（30 Hz・20 ms・0.5 mm）。

**落下の検出**（S4DREC の fall_as_is、成立した 48 本）

| 場合 | sim_v1 | R10_L50_s05 | R30_L20_s05 |
|---|---|---|---|
| P2 そのまま（指を開いて落とす） | 48/48、落ちてから 0.11 s（0.07〜0.13） | 48/48、0.16 s（0.12〜0.18） | 48/48、0.10 s（0.09〜0.12） |
| P2S を真似た開き幅（指が空を掴んで閉じる） | 48/48、0.18 s（0.13〜0.22） | 48/48、0.22 s（0.17〜0.26） | 48/48、0.16 s（0.15〜0.18） |

（中央値、括弧は 10〜90%。P2S を真似た開き幅は、小さなシミュレーションで測った形: 0.07 s は変わらず、その後 8 cm/s で 0 へ。）
どの場合も、誘発の成立（立方体が机で静止）より 0.4〜0.5 s 早い。P2H の記録でも 52/52。

**発火のときの手の位置**（P2 そのまま、sim_v1）: 手先の高さ 15 cm、落ちた所から 3.1 cm 進んだ所。着地した立方体から水平に 1.2 cm。
止め方ごとの止まる位置の見積もり:
- `stop=measured`（既定）: 発火の時点の手先で止まる。着地した立方体から約 1〜2 cm（P2H の放したときの 1.25 cm とほぼ同じ）。
- `stop=freeze`: 参照が腕より約 3.5 cm 先にあるので、落ちた所から 6.7 cm 先、着地した立方体から 4.1 cm（2.5〜4.9）で止まる。
- 反射なし: 最初の新しい塊が動くまでに 10.4 cm 進む（段階 4 の記録。手は閉じている）。

**把持失敗（P1）の空掴みの検出**（S4DREC・S4B2 の P1、成立した 191 本）: 191/191。閉じる指令から 0.95〜1.0 s（指が 8 cm から閉じ切る
のに約 0.65 s、そこから 0.3 s）。成立の判定より約 1.0 s 早い。方策が自分で開き直すのは、反射の発火より中央値 0.8 s 後（90% 点 6.6 s 後）。
空掴みの検出は望ましい働きとして数え、誤発火とは分ける。

**誤発火（落下の発火で、本当は落としていなかった）**

| 記録 | 試行 | 誤発火のあった試行 | 本当の落下（自然に滑った） |
|---|---|---|---|
| S4T1HC（健康診断） | 132 | 0 | 0 |
| S4B2 *_ext（自然） | 207 | 0 | 1 |
| S4B1（3 個の連続タスク） | 150 | 0 | 3 |
| S4B2・S4DREC の P1 | 250 | 0 | 3〜4 |
| 診断の記録（S4DRTC・S4DSTART・S4K） | 576 | 1（箱の壁を指で挟んで持ち上げた） | 3 |

センサの模型を変えても同じ。

**自然な試行の空掴み**（誤発火ではなく、本当に空を掴んで 0.3 s 以上閉じたまま）: S4T1HC で 45/132 本（成功した試行では 18/105 本）、
S4B2 *_ext で 53/207 本（成功した試行で 24/176 本）。反射を入れると、成功した試行の 14〜17% で、空掴みの後に約 1 s 止まってやり直す。
これが成功を減らすか増やすかは、記録からは分からない（第 8 節の自然な試行の比較で見る）。

**置き損ね（P3）に反射は効くか**: P3 は、方策が箱の上で開を出したのをきっかけに、誘発が閉のまま運んで、ずらし先で開き、
立方体が静止するまで手を止めて開いたまま保つ。運んでいる間の「方策の開閉」は記録にない（誘発が上書きした）。
- 方策が開を出し続けていたなら、検出は「意図した放し」として最初に戻り、ずらし先で開いても発火しない（記録の再生で 0/73）。
- 方策が閉に戻していたなら、ずらし先で開いた 0.1〜0.2 s 後に発火する（73/73）。そのとき手は止めて開いたまま保たれており、
  反射の止め方は誘発のしていることと同じ。違いは、古い塊を捨てて、待ちの後に新しい観測から推論することだけ。
- つまり P3 では、反射は効かないか、誘発と重なるだけ。P3 の誘発そのものが「手を止めて指を開いたまま待つ」を含む。
  それでも P3 の 30 s の復帰は 4/31 と低いので、手を止めるだけでは足りない場面もある（未確認）。

**画像の手がかりで発火する決まり**（`cue_jump_m=0.08`）: 自然な試行の 76〜90% で誤発火。使えない。

**外から加わる力の推定（`O_F_ext_hat_K`）を 2 つ目の信号に使えるか**: 記録に力がないので、数字の見積もりだけ。立方体 50 g の重さは
0.49 N。運ぶ間の手の加速度は小さい（中央値 0.07、99% 点 0.6 m/s²。S4DREC の落ちる前 1.5 s）。ただし Franka の外力の推定は、
関節のトルクセンサと動力学の模型から出す値で、姿勢によって数 N のずれがあると言われる（**仮定**。実測していない）。運ぶ 20〜30 cm の間に
0.5 N の段差を 0.1〜0.2 s で見分けるには、ずれの変化が 0.2 N 以下でなければならず、難しいと見る。主の信号には使えない。腕が止まって
いるとき（持ち上げた直後など）に、持つ前と持った後の重さの差（0.5 N を 0.5 s 平均）を見る確かめなら使えるかもしれない（未確認）。

再生の道具と結果: 作業用のフォルダ（`scratchpad\reflex\offline_eval.py`・`offline_eval2.py`・`out\`・`out2\`）。リポジトリには入れていない。

## 7. 実機に移すときの前提と未確認の点

**前提（仮定）**
1. Franka Hand の状態（`franka::GripperState`: width・is_grasped・time）は、別のスレッドで `Gripper::readOnce()` を回して読む。
   頻度は 10〜30 Hz、届くまでの遅れは 20〜50 ms、開き幅の雑音は 0.5 mm 程度と仮定した（franka_ros の gripper の状態の既定の頻度 30 Hz
   を目安にした。実測していない）。
2. grasp() で握っている立方体が抜けると、ハンドは力の制御のまま閉じ続け、開き幅は 0 へ向かい、is_grasped は偽になる。
3. `Gripper::grasp` と `move` は、終わるまで戻らない呼び出し。反射で開くときは、`Gripper::stop()` で grasp を止めてから `move(0.08, speed)`
   を別のスレッドで出す。
4. 「止める」は、腕の制御の参照（直交座標の姿勢、または関節の位置）を、発火の時点で測った姿勢に置く。libfranka の制御の周期（1 kHz）の中で
   参照を跳ばさないよう、速さの上限（0.25 m/s）で寄せる。
5. 実機の立方体は 4 cm の PLA、約 50 g。grasp の力は数十 N。
6. 実機での落ちる原因として、次を想定する（今は作っていない）: 人の手で引き抜く・はたき落とす（P2S で真似た）、ヨーのずれによる角・縁の掴み
   （シミュレーションの立方体のヨーは ±30°、指のヨーは固定）、浅い掴み、箱の壁や他の立方体への衝突。

**未確認**
1. 上の 1〜3（頻度・遅れ・雑音、抜けた後の指の動き、stop と move の切り替えにかかる時間）。実機で開き幅の時系列を記録して確かめる。
2. 斜めに握ったとき（5.2 cm）に grasp() が失敗を返すか、そのまま握り続けるか（シミュレーションの is_grasped の窓は 3.5〜4.5 cm）。
3. 箱の壁を挟んで持ち上げたときの誤発火（記録の再生で 576 本に 1 本）。
4. 外力の推定のずれの大きさ（第 6 節の終わり）。
5. 空掴みのたびに止めてやり直すことが、方策の自分での立て直しを邪魔しないか（第 8 節で見る）。

## 8. 確かめの実験の提案（まだ回さない）

問い: 反射を入れると、落下からの復帰が P2H と同じくらい上がるか。自然な試行の成功を下げないか。

**腕**: 反射の入（`--reflex`）と切。同じ種・同じ順で両方を回し、種ごとの対で比べる（McNemar の正確な検定）。

**条件と本数**（試行の時間の目安: 誘発 約 115 s、自然 約 33 s。GPU 1 枚で続けて回す）

|---|---|---|---|---|---|
| 主 | R1v3 | 落下 P2（指を開く） | `--induce P2` | 50 | 成立 約 24 本。切 0/23 → 入 約 10/25（P2H と同じ）なら、食い違い 8〜10 本が全部入の側で p ≈ 0.004〜0.002 |

## 9. 危ないところ

- 誘発が行動を上書きしていた間の方策の開閉は記録になく、オフラインの評価は「閉のまま」とみなした。実際の実行で発火が遅れたり、
  出なかったりするかもしれない（入の腕の事象で確かめる）。
- 反射が開いた後も方策が閉を出し続けると、空掴み → 反射 → やり直し → 空掴み、を繰り返しうる（1 回およそ 1.5〜2 s）。
- `stop=measured` は参照を後ろへ戻すので、腕は一瞬減速して戻る。速さの上限は 0.25 m/s。腕の制限層（躍度・加速度）を超えないことは
  シミュレーションで確かめる（G3 の監査）。
- 反射は run（単発）だけに入れた。task（3 個の連続タスク、E7）には入れていない。
- 引き抜き P2S は、立方体の位置と速度を直接書く（人がしっかりつまんで引く手の代わり）。力で引くと、静止摩擦が切れた瞬間に
  立方体が 6〜10 m/s で飛んだので、この形にした。指と腕にかかる反力の大きさは、実際の人の手とは違いうる。
- 引数は検証の記録で決めた。同じ記録で良く見えているので、新しい種では少し悪くなりうる。
