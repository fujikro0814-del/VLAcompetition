# 構成の変更: 目標の位置を上位層から VLA に渡す（2026-09-26、決裁 0048）

## 1. 何を変えたか

| | 変更前（計画書 v2） | 変更後 |
|---|---|---|
| 流れ | 日本語の指示 → LLM → 色 → 指示文（`put the {color} cube in the box`）→ VLA | 日本語の指示 → LLM → 色 → **色の判定（俯瞰画像）→ 目標の位置の手がかり** → VLA（**指示文と手がかりの両方**） |
| VLA の状態 `observation.state` | 15 次元（手先の位置 3・向き 3・指 2・関節 7） | **18 次元**（15 ＋ 手がかり 3: `cue_x`・`cue_y`・`cue_visible`） |
| 色の判定の部品 | Step I で作る予定（完了判定用） | `src/recovla/perception/color.py` に作り、K1 の手がかりと Step I で共用する |

指示文は残す。VLA は指示文と手がかりの両方を受け取る。

## 2. 理由（K1 の結果。数字は `docs/E_報告.md` と掲示板 0037〜0046 のまま残す）

VLA 単体（SmolVLA、`lerobot/smolvla_libero` から、VLM 固定・行動エキスパートのみ）では、指示の色と画像の中の立方体を結びつけられなかった。

| 試したこと | 結果 |
|---|---|
| K1（配置 30・90 本、8000 手） | E6 正答率 31.3%（3 択の偶然と同程度）、閉ループ成功 2/30 |
| 診断 D1（予測のずれの向きと正解のずれの向き） | cos の中央値 −0.09（向きがそろっていない）。到達点は 3 つの立方体の重心へ寄る |
| 診断 D2（学習データで、正しい指示の損失が最小になる割合） | 57%（偶然は 33%） |
| 診断 D3（指示の経路） | 学習時と推論時でトークン・覆い・画像・状態が一致（前処理の誤りではない） |
| LoRA の枝（VLM の 8〜15 層、最初の 2 秒を 5 倍、配置 100） | E6 正答率 31.3%、閉ループ成功 1/30、D2 51% |
| 固定した VLM の特徴の読み取り（リッジ回帰、配置で分けた 5 分割、`outputs/k1/vlm_probe.json`） | **画像のトークンから 3 色の位置: 誤差の中央値 3.9 cm、指示のトークンから指示した立方体の位置: 7.9 cm（基準＝常に 3 個の重心を答えた場合: 9.1 cm）** |

最後の行の対比から、画像の特徴には立方体の位置が入っているが、指示のトークンには指示した立方体の位置がほとんど入っていない、つまり指示と位置を結びつける段で情報が途切れていると読む。（全トークンからの読み取りは 9.1 cm だったが、300 例に対して次元が約 13 万と大きすぎた影響がありうるので、結論には使わない＝決裁 0050。）大きな VLA でも指示が無視されやすいことは知られた弱点で、手順書 §6 の「色の差を強める・間隔を広げる・2 色に減らす」はこの弱点に当たらないと決裁が判断した（0048）。本題の復帰デモの比較（E3、R1 と N1 の比較）は、目標の選び方と独立なので影響を受けない。

## 3. 手がかりの定義（`recovla.perception.color`、`recovla.data.vla_state`）

1. 俯瞰カメラの描画（方策の画像の反転の前）の各画素を、色 c の画素 ＝「チャンネル c ≥ `min_value`、かつ ほかの 2 チャンネルの大きい方より `min_margin` 以上大きい」で分ける
2. 指示の色の画素の重心 (u, v) を、俯瞰カメラの較正の値（内部・外部。静的なカメラなので模型から読む）で光線にし、机の面（立方体の中心の高さ 0.02 m）との交点 (x, y) を手がかりにする
3. 画素が `min_pixels` 以上なら旗 1。未満なら旗 0 で、最後に見えた (x, y) を保つ（一度も見えていなければ配置の範囲の中心）
4. 学習データでは 10 fps のこまごとにエピソードの頭から順に、推論では方策を呼ぶたびに計算し直す（落下の後も追う）。試行の頭と、指示の色が変わったときに保った値を捨てる

**ズルにしないための決まり（0048 の 2）**
- 手がかりは学習でも推論でも俯瞰画像からだけ計算する。シミュレータの真値は方策の入力に入れない（台本と成否の判定は真値のまま）
- 閾値は学習データの種（K1 の 10000〜10099）だけで決めて `configs/default.yaml` の `planner.color_detect` に固定した（`scripts/23_color_fit.py`: 保存したこまから状態を組み直してセグメンテーションで正解づけし、3 色の画素の F1 の平均が最大の組。`min_value` 20・`min_margin` 40、F1 0.937。写っていないのに検出したことは 0 回なので `min_pixels` 1）。選択用・最終評価用の種では調整しない

**正規化**: 旗は学習データで一定になりうる（K1 では常に 1）。標準偏差 0 で割らないよう、旗の次元だけ正規化の値を平均 0.5・標準偏差 0.5 に固定する（`vla_state.CUE_FIXED_STATS`。変換が `meta/stats.json` に書き、`--verify` が例外として確かめる）。

**学習と評価で同じものを使う仕組み**: 変換は `conversion.json` に `target_cue`（閾値・較正・定義）を書く。評価の入口（`vla_observation.PolicyObservationBuilder`）は、学習の `conversion.json` に `target_cue` があれば同じ部品で手がかりを足し、閾値が設定と違えば止まる。

## 4. 単体検査（0048 の 3、`scripts/24_cue_check.py`、`outputs/k1/cue_check.json`）

K1 の 300 本・83,818 こま（20 Hz）。見えないこまは 0（俯瞰からは、腕の下でも目標が写っている）。

| 区間 | 差の中央値 | 95 百分位 | 最大 |
|---|---|---|---|
| 接近 | 0.14 cm | 0.56 cm | 1.34 cm |
| 把持 | 0.41 cm | 0.84 cm | 1.69 cm |
| 搬送 | 16.2 cm | 18.8 cm | 20.6 cm |
| 設置 | 4.4 cm | 8.5 cm | 9.4 cm |
| 退避 | 2.6 cm | 3.7 cm | 5.6 cm |

搬送・設置の差は、持ち上げた立方体を机の面の高さへ投影した視差（手がかりは画像だけから計算するので、立方体の高さは使わない）。退避は、箱の底が机より 1 cm 高いことと、壁による隠れの影響。

**持ち上げると、手がかりは机の面に投影されて跳ぶ。** 立方体が机を離れると、俯瞰カメラから見た重心の光線と机の面の交点は、実際の立方体の真下からカメラと反対の側へずれる（搬送中の中央値 16.2 cm、最大 20.6 cm）。置いて机（または箱の底）に戻ると、またほぼ真下に戻る。学習と評価で同じ計算をするので直さない（決裁 0050）。
